# Rally 云端模式与 Android 客户端

2026-11-21 实施记录。产品决策以 `superagent/00-问答记录.md` 为准。范围是一人的一套云端 Agent、多台受信设备，不是多租户服务。

## 运行边界

| 入口 | 执行位置 | 存储与能力 |
| --- | --- | --- |
| Windows 本地 | 原 Electron Supervisor | 原 `~/.rally`、工作区、通知、终端和浏览器 |
| Windows 云端 | VPS | 桌面只负责连接、配置与消息界面；本地 Supervisor 不启动 |
| Android 云端 | VPS | APK 内置 GeckoView 与共用 React 前端，设备只持有加密连接凭据和界面偏好 |
| VPS 控制台 | 接入服务 | 需管理密钥登录，签发/吊销设备、查看最近在线、控制新设备配对 |

主 Agent、Worker、文件、作业、调度、MCP 与连接器都在 VPS 执行。多个客户端共享同一实例。退出或换服不会停止原服务器上的任务。本地与云端任务、历史和配置不迁移。云端首版暂缓用户交互终端、内嵌浏览器、私有服务预览、系统通知。

## 最小业务改动

- `src/main/business.ts` 从原 IPC 抽出业务处理器。本地 IPC 与无头运行时复用；所有桌面主进程通信仍使用 `src/shared/ipc.ts` 声明的通道。
- `src/shared/client-api.ts` 保留现有 `window.rally` 调用形状。`connection.ts` 根据模式选择本地 IPC 或原生网络桥；确认连接后才挂载应用。
- VPS 使用两个 systemd 服务：`rally-runtime` 运行现有 Supervisor；`rally-control` 提供控制台、鉴权和业务白名单转发。两者通过权限受限的 Unix socket 通信，运行账号分离。
- 接入采用协议版本 1：JSON 请求和带 epoch/序号的增量轮询。断档/重启后发完整快照；断线禁写并重连，不重放危险操作。
- 聊天请求有设备范围的持久请求 ID，防止响应丢失导致重复派发。提供商/MCP 配置带版本，拒绝覆盖其他客户端刚保存的内容。

业务配置仍由现有存储层管理。仅新增设备凭据摘要、请求去重的 SQLite 数据库，没有引入外部队列或数据库服务。连接器在 Linux 使用独立文件密钥加密，Agent 账号无法读取控制台管理密钥。

## 连接与存储隔离

Windows 的 `connections-v1.json` 独立保存模式、URL、实例 ID 与系统加密令牌。云端页面按规范化 URL 和实例 ID 使用独立 Electron session partition；本地仍使用原分区。换服先验证新连接，成功后重启进入新分区；失败保留原连接。同一地址重装服务器后必须重配对。可以切回已有服务器，或输入新接入密钥替换原设备凭据。

Android 的连接偏好与 Keystore 加密令牌由原生层持有，GeckoSession 使用连接 profile 作为 context ID 隔离页面存储。URL 是 API 地址，不是页面导航地址。应用界面来自 APK 内置扩展；只有该扩展的顶层页面可以调用受限消息桥。外链交给外部浏览器。切换时销毁旧会话，断开旧请求，拒绝迟到响应。

设备接入密钥为一次性邀请，配对后换取独立设备令牌。服务端只存摘要。管理密钥不能配对，设备令牌不能访问控制台；控制台吊销后，后续请求和尚未交付的响应拒绝该设备。HTTPS 为默认部署建议；按用户要求允许 IP:端口 HTTP 测试。

提供商 API Key 和 MCP 的参数、环境变量、Headers 不回传。已保存项以服务器校验的引用表示，客户端可沿用、替换或删除；变更提供商 URL 必须重新输入 Key。业务配置以服务器为准，设备保存外观偏好和可丢弃的读取缓存。

### 启动缓存与数据增长

设备使用 IndexedDB 缓存人设、主会话、任务、工作区和脱敏模型列表，缓存按规范化 URL 与实例 ID 双重隔离，同时受 Windows session partition / Gecko contextId 隔离。输入中的密钥与 MCP 配置不进入缓存。事件状态与游标原子存储，恢复时先显示缓存，再按 epoch/seq 续传；连接确认前拒绝写操作，不自动重放发送。

首次快照直接供组件初始化，不再丢弃后重复拉取。流式更新最多每 1.5 秒落盘一次，页面隐藏时尝试立即保存。单实例缓存上限为 4M UTF-16 字符（约 8 MiB）；超过上限仅保留人设、记忆路径摘要并清除增量游标，下次完整同步。缓存损坏或不可用不会阻止连接。

当前服务器增量窗口为最多 256 条 / 8 MiB。服务重启或游标过期会回退完整快照；完整主会话和归档任务仍随历史增长，历史分页及任务详情按需加载尚未实现。因此缓存改善常规重启和闪烁，但不是无限历史规模的完整方案。

## 安卓内核与移动界面

用户于 2026-11-21 确认接受更大 APK，改为内置 GeckoView，固定 `160.0.20261116130455`。使用官方 Maven 包、Gradle wrapper 和依赖锁，不依赖设备的 Android System WebView。APK 与 Windows 继续打包同一份 renderer。Gecko 与 Chromium 仍是不同引擎，布局使用两者支持的 Web API。

移动适配包括：安全区域与输入法避让；聊天头部独立栅格；输入框/弹出模型选择器约束；右栏以整屏工作台展开；设置目录/详情切换；系统返回键逐层返回。保留现有 token、玻璃卡片与品牌风格。Android 输入法 Enter 换行，发送使用按钮或外接键盘 Ctrl+Enter。

启动页在前端资源加载失败、脚本错误或连接失败时显示明确错误与重试。打包检查同时验证 ZIP 本地文件头和中央目录路径、入口依赖资源及内核存在，防止 Windows 资源路径反斜杠再次造成白屏。

## 构建与 Release

```bash
npm ci --ignore-scripts
npm run hydrate:model-data
npm run build
node scripts/cloud/build-android.mjs --debug
npm run dist
npm run build:server
# Linux CI：
bash scripts/cloud/package-linux.sh
```

Android 构建需要 JDK 17、Android SDK Platform 37.2 / Build Tools 36.0.0。脚本通过 Gradle wrapper 拉取校验过的固定 Gradle。首次调试构建生成本机测试签名；保管 `.artifacts/android-debug.p12` 可继续覆盖测试包。

`.github/workflows/release.yml` 接收与 package.json 匹配的 `vX.Y.Z` 标签，分别构建 Windows、Android、Linux，全部成功后创建带 SHA256SUMS 的 GitHub **草稿 Release**。工作流不含 VPS 凭据，也不自动部署用户服务器。没有推送标签时不会发布。

正式 Android 签名需配置仓库 Secrets：`ANDROID_KEYSTORE_BASE64`、`ANDROID_KEY_ALIAS`、`ANDROID_STORE_PASSWORD`、`ANDROID_KEY_PASSWORD`。固定签名用于后续覆盖升级；测试签名与正式签名不同，正式包不能直接覆盖测试包。

| 附件 | 内容 |
| --- | --- |
| `Rally-X.Y.Z-setup.exe` | Windows 本地/云端二合一 NSIS 安装器 |
| `Rally-X.Y.Z-android.apk` | 固定内核、正式签名的 Android 云端客户端 |
| `rally-server-X.Y.Z-linux-x64.tar.gz` | Node 24.11.1、运行依赖、业务代码、控制台、systemd 和安装说明；不含完整客户端前端 |
| `SHA256SUMS` | 三类安装文件摘要 |

部署、升级与备份步骤见 `deploy/linux/README.md`。已在用户 Ubuntu 22.04 x64 VPS 安装验证，本次测试采用 HTTP IP 直连；不是从尚未发布的 GitHub Release 下载。

## 验证与边界

开发验证包括 Node/renderer 类型检查、构建、指定本地 IPC/关闭测试、连接分区测试、Windows/Linux 无头协议测试。协议测试覆盖管理/设备权限隔离、错误凭据、设备吊销、协议冲突、快照补齐、请求去重、配置持久化与版本冲突。

Linux 包内使用 offline faux provider 验证主 Agent 派发、人工批准、Worker shell/文件读写、任务汇报与主对话转述，不调用真实模型 API。首次测试 APK 的白屏通过用户提供的 ADB 定位为 ZIP 资源路径错误；随后按用户选择迁移到内置内核。

仓库完整 `npm run typecheck` 仍受已知 `packages/ai/test` 两个模型数据相关测试文件阻塞；不能把该命令报告为通过。2026-11-21 用户已确认配置、对话、连接器、任务查看和多端同步的真实功能验收通过；本次新增缓存和移动布局仍需用户体验验收，不把离线测试当作真实 API 成功。
