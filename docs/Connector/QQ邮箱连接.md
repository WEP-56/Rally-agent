# QQ 邮箱连接

QQ 邮箱是 Worker 工具。主 Agent 知道它能做什么，会派发任务给 Worker；收件箱不会接入主对话，也不会自动回复。

## 配置

1. 登录 [QQ 邮箱网页版](https://mail.qq.com/)，进入设置中的账号或第三方客户端设置，开启 **IMAP/SMTP 服务**，按提示生成客户端授权码。
2. 在 Rally 打开「＋ → 连接」（`Ctrl+4`），展开 **QQ 邮箱**。填写 `@qq.com` 邮箱地址和新生成的授权码，点击「验证并连接」。不要填写 QQ 登录密码。
3. 验证会登录 `imap.qq.com:993` 并以只读方式打开收件箱，再验证 `smtp.qq.com:465` 登录，两个端口均用 TLS。验证不会发信；验证通过后才会通过系统凭据加密保存授权码。不要把授权码发进聊天。

换绑或断开会撤销既有 Worker 的连接权限和仍在等待的邮箱工具审批。重新连接后，创建任务或重新启动原 Worker 以加载工具。工具风险档会保留，换绑不会重置。若想让该授权码在 QQ 邮箱端也失效，请在 QQ 邮箱设置中撤销它。

## 工具权限

在「连接 → QQ 邮箱 → 管理」调整四个工具的风险档；未连接时也能展开卡片预先设置。检索、读取、保存附件默认可逆，发送/回复默认不可逆，需要用户确认。若希望已授权的定时任务直接发信，把「发送或回复 QQ 邮件」改为「有对外代价」，后续调用会直接执行并提示、留审计，无需额外的“始终允许”按钮。

保存立即落盘，重启后保留；下一次调用使用新设置，已发出的确认仍须处理。其余工具也支持改档，不只是发信开关。详见[统一约定](README.md#工具与权限的统一约定)。

## 能力与限制

- 支持按发件人、主题、内容、起始日期和未读状态检索收件箱。每次最多返回 30 封，读取不改变已读状态。首版读取纯文本和附件清单，原始邮件不超过 16 MiB。
- 保存附件到任务产物目录，使用新文件名并返回原文件名和类型。发送或回复支持明确指定收件人和抄送人；最多附加 5 个任务产物目录内的文件，总计不超过 10 MiB。
- 发信设置为不可逆时，确认卡片展示发件人、收件人、主题、正文和附件清单。确认后提交卡片对应的那份内容，模型不能代确认。拒绝、超时或确认前断开连接不会发送。其他档位直接提交；附件在提交或确认前固定内容，发信始终记录尝试与结果。若遇到发送结果不明，先到 QQ 邮箱确认收件情况，再决定是否重试。
- 授权码不会提供给模型。Worker 读取的邮件内容会作为工具结果交给你配置的 Worker 模型，可能随任务历史保存在本机；如果模型服务部署在远端，读取前请考虑邮件内容是否适合交给该服务。

## 真实账号验收

1. 使用授权码连接后点「验证连接」，确认能显示最近验证时间。重启 Rally，确认同一账号仍在。
2. 使用含有测试附件的未读邮件，要求 Rally 按主题查找、读取并保存附件。核对结果、产物目录中的文件，以及 QQ 邮箱中的未读状态。
3. 保持发送为「不可逆」，指定自己控制的测试收件地址，让 Rally 准备一封回信。核对桌面卡片，第一次点「拒绝」，确认未收到；再次发起并点「确认发送」，核对收件数量、正文、邮件线程和附件。也可留一项审批等待，断开连接后确认卡片关闭。
4. 将发送改为「有对外代价」，明确要求再发送一封测试邮件，确认无需重复批准、任务有外部操作提示。改回「不可逆」，确认下次发送重新等待；重启后核对所选档位保留。

实现复用 [ImapFlow](https://imapflow.com/) 操作 IMAP、[MailParser](https://nodemailer.com/extras/mailparser) 解析邮件和附件、[Nodemailer](https://nodemailer.com/smtp) 提交 SMTP，并复用 Rally 已有的凭据加密、任务产物目录和桌面审批卡。
