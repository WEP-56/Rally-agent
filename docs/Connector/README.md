# Connector 文档索引

## 工具与权限的统一约定

连接器提供的工具统一放在「连接」页对应应用的「管理 → 工具权限」中。无论底层是 MCP 还是原生工具，用户都在连接器里查找和设置；「设置 → MCP」管理用户自行配置的 MCP 服务，不重复展示内置连接器工具。

- 工具清单来自连接器定义，首次使用前即可查看和设置，不依赖任务曾发现工具；列表不表示账号已连接或工具已经加载。QQ 机器人目前仅传递主对话消息，没有 Worker 工具。
- 前端使用 MD3 分段控件选择风险档，读取和保存仍通过 `connectorTools.getState/setTier`；保存期间禁用选择，失败显示错误。视觉迁移不改变工具登记、默认风险档或执行时校验。
- 复用三档权限：`reversible`（可逆）直接执行；`external`（有对外代价）执行并提示、留审计；`irreversible`（不可逆）进入现有审批流程。权限档决定调用流程，不改变工具实际能做什么。
- 飞书三项只读工具，以及 QQ 邮箱的检索、读取、保存附件，默认可逆。QQ 邮箱发送/回复默认不可逆，仍由用户确认；用户可在连接器中改为有对外代价，以支持已授权的无人值守发信。邮件提交无论档位都记录尝试与结果。
- 权限保存在执行主机的 `settings.json.mcpTiers`，继续沿用已有飞书配置，不增加“始终允许”按钮或另一套批准记录。重启、断开和换绑后保留同一工具的设置。
- 每次调用读取当前权限；保存从下一次调用生效，已经等待中的确认不会自动放行。连接、工具总开关和 Worker 加载规则仍各自生效，改权限不会连接账号或为当前 Worker 加载缺失的工具。
- 新增工具必须同步维护 `src/main/connector-tools.ts` 中的名称、中文用途与默认风险档，并在执行前接入风险校验、审计与审批。飞书清单和实际服务共用官方 schema；原生工具也必须有对应登记。权限数据不作为新的动态上下文注入模型。

## IM 消息收件箱

飞书与 QQ 私聊共用[用户消息收件箱](../用户消息收件箱.md)：忙时先保存并排队，不再要求用户稍后重发。连接器回调只等待持久接收，模型完成后按原来源回传；断线保留结果，换绑不误投，失败可只重发文字。长时间排队可能超过平台回复时限，完整结果仍留在 Rally。
