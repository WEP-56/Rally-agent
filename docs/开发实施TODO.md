## 24/7 个人代理讨论：初始想法

以下保留初始想法；后续范围以文末的 2026-11-25 共识为准。

- 用户消息收件箱与队列机制
- 权限与批准：等待用户批准的持续时间，权限的放宽（始终允许按钮，比如目前的rally，测试发现，布置了一个搜集信息发送邮件的任务，但邮件发送必须向用户申请同意）
- 定时任务能力的扩充。工作类型扩充（比如每隔几小时一次，在晚上几点到几点不做这种场景）、中断处理
- worker的信息补充。考虑为worker提供上下文或记忆（需要讨论）
- 主动性的问题 - 主Agent的拒绝权力。发现的场景：worker重复汇报一些问题，主AGENT全都只能回答。IDEA有不合适的地方，主AGENT也必须回答。或许给主AGENT拒绝系统消息的权力，对自主性
- 对真实世界的感知问题，Rally可能缺了一些tools，如，在用户告诉了rally自己的位置之后，它应当可以通过工具快速得知用户的时间、天气等
  - 其它主动性提升：对idea教练的提升，周报、早报。用户使用频率收集（主要是打开rally的时间），以定制idea教练的出现（在高频的打开rally的时间之前，发出点子）
  - 一些取舍：仍然不在system prompt或程序测，让LLM主动获取用户隐私。而是让LLM有主动借机询问的意识。
