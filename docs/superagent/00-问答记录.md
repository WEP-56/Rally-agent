# Superagent 问答记录

- 用途：逐轮记录问答的问题、选项、用户选择与派生结论。它是 `docs/superagent/` 各分册与 [改造计划.md](../改造计划.md) 决策表的**唯一依据**；分册与本文冲突时以本文为准。
- 标注沿用改造计划：**【已定】**＝用户已拍板；**【建议默认】**＝我的推荐，可推翻；**【事实】**＝源码可查；**【推断】**＝未运行验证。
- **派生默认值**＝由【已定】答案推出、用户尚未逐条确认的细节，均为【建议默认】，可推翻；被推翻时在此处改写并注明轮次。

## 第 1 轮 · 角色与协议基石（2026-11-08）

### Q1 主 agent 自己能动手到什么程度

- 选项：只读侦察＋派发／纯调度（无任何文件、命令工具）／全工具＋倾向派发
- **【已定】只读侦察＋派发**：主 agent 只有只读工具，用于理解意图、写派发、直接回答小问题；任何写文件、执行命令都必须派给 worker。边界由工具集强制，不靠提示词自觉。

派生默认值：

1. 主 agent 工具集＝只读文件工具（`read/grep/find/ls`）＋只读 git 查询（`status/log/diff/show`，以独立工具提供，**不给 shell**）＋联网检索（`web_search/fetch_page`）＋任务工具组。无 `bash/powershell/write/edit/file_delete`。
2. 提示词另加约束（沿用 dsh `prompts/shared.md`）：只读工具只用于理解意图、选派发目标、回答事实性小问题；**不得为解决 worker 的技术问题亲自调查**，不替 worker 做技术决定。
3. 主 agent 自身没有可写动作 → 内门只作用于 worker，主 agent 的工具调用不过门控。

### Q2 多个 worker 并发改同一目录时怎么隔离

- 选项：同目录写互斥／git worktree 隔离／完全共享并行＋乐观锁
- **【已定 2026-11-08，推翻"同目录写互斥"】不做锁**：宿主不实现任何锁、租约、目录归属或阻塞式 `acquire`；并发单元只有名额。理由：单人桌面、并发默认 2，锁的维护成本高于收益；静默覆盖风险由 `scope` 警告、`changedFiles` 记录与"读后被改"检测兜底。详见 04 §2。

派生默认值：

1. 派发时声明 `cwd`、`mode: "write" | "readonly"` 与 `scope: string[]`（预计写入的路径范围，绝对路径或相对 cwd）。
2. `scope` 与**运行中任务**的 `scope` 路径段前缀交叉时：**不阻止派发**，返回一条警告，事件流记 `task_scope_overlap{taskId, withTaskId, paths}`。
3. 不新增排队原因；队列仍只有 `dependency_failed > dependency > capacity`。原 `write_lock` 文案与"等锁不占名额"规则一并删除。
4. 主 agent 提示词纪律：派发前检查运行中任务的写范围；重叠时要么串行，要么明确告知用户"这两个任务会并行写同一片区域"，用户坚持则照派。
5. 任务进终态时记录 `changedFiles`（复用访问痕迹）；`write/edit` 的"读后被改"检测保留，防 IDE 手改与 shell 写入。
6. 构建产物隔离不能靠纪律：`out/`、`dist/`、`node_modules/`、`.vite/` 必须加任务独立后缀（如 `RALLY_TASK_ID`），无法加后缀的构建步骤串行（04 §2.3）。

### Q3 worker 汇报后主 agent 是否自动"醒来"

- 选项：关键节点唤醒／只插卡片不发言／完全静默
- **【已定】关键节点唤醒**：完成、受阻、失败、需要用户决定时唤醒主 agent；普通进展只更新右栏。

派生默认值：

1. 唤醒报告：`ready`、`blocked`、`failed`、`dropped`、带问题的报告（`question`）。`progress` 只更新右栏、不唤醒（同 dsh `reportRelay`）。
2. 主 agent 空闲 → 新起一轮：主对话先出一条**系统行**（如"T-1045 已完成"，不是用户气泡），再接主 agent 发言。主 agent 忙 → 以 steer 并入当前轮（当前工具调用结束、下次模型调用前注入；【推断】待 Pi 实测）。
3. 合并与顺序：约 2 秒窗口内到达的多条汇报合并成一次唤醒；中继按到达顺序、至少一次投递、按 `relayId` 幂等（dsh `relay` effect 模式）。
4. 中继内容：任务卡（id、标题、状态、阶段）＋摘要（≤600 字，超出截断并给 `task_read` 指针）。主 agent 要细节就用 `task_read` 读汇报与产物，**不读 worker 完整对话**（dsh："Never read detailed transcripts"）。
5. 发言门槛（dsh `000-philosophy`）：只在用户能用上结果、或必须由用户行动时发言；没有新信息时允许空结束。

### Q4 派发给 worker 的简报怎么写

- 选项：原话＋目标＋验收（我的推荐）／主 agent 全权撰写／原话转发＋短备注（dsh 式）
- **【已定】原话转发＋短备注（dsh 式）**：系统逐字引用用户原话，主 agent 只加一条短备注；不写验收标准与实现方案，worker 自己从原话推导需求。

派生默认值：

1. `task_dispatch` 参数：`title`（≤40 字）、`quotes: messageId[]`（≥1 条）、`note?`（≤30 词，中文按分词计）、`cwd`、`mode`、`dependsOn?`。**删除** `brief/acceptance`。
2. 原话由系统按消息 ID 从主对话**逐字复制**（含附件），主 agent 无法改写。worker 首条消息＝标题＋原话＋备注＋执行环境（cwd、mode、上游任务结果）。
3. 多轮澄清：`quotes` 可引用多条用户消息；当某条用户消息只是确认主 agent 的提议（如"就按方案 B"）时，允许连同被确认的那条主 agent 提议一起引用，并标注"主 agent 提议 · 用户已确认"（dsh `communication.md` 同理）。→ 待确认
4. 备注只写路由背景或用户的明确约束（如"用户要求先别动 API"），**不得**写实现方案、验收标准、步骤。
5. 派发回执改为：taskId＋标题＋一句话说明"要做什么"，不再含验收标准。
6. 外门审阅内容改为：标题、原话、备注、cwd、mode、依赖。用户可改标题、备注、cwd、依赖，也可追加一条"用户补充说明"（视同新原话）后批准。
7. `task_steer`（给运行中任务追加要求）同理：转发用户原话＋短备注，不由主 agent 改写成新指令。
8. worker 提示词：需求以原话为准，备注只是背景；完成与否由 worker 依据原话判断，并在汇报中给出证据。

## 第 2 轮 · 工作区与任务边界（2026-11-08）

### Q5 主对话、任务与项目目录的关系

- 选项：默认项目＋可指定／单一托管工作区／项目即对话
- **【已定】默认项目＋可指定**：标题栏显示"当前项目"，它只是默认值；任务也可显式指定其他目录；未打开项目时落到 Rally 默认工作区。主对话本身不绑定目录，切换项目不必新开对话。

派生默认值：

1. "当前项目"存在 Rally 配置里（含最近项目列表），每轮作为动态上下文告诉主 agent（如"当前项目：C:\proj（git，分支 main）"）。
2. 主 session 的 cwd 固定为 Rally 自己的目录（如 `~/.rally/agent/main/`），**不随项目切换**。主 agent 只读工具接受绝对路径，相对路径按当前项目解析。
3. 任务 `cwd` 默认等于当前项目，主 agent 可指定任意绝对路径；外门审阅卡片醒目展示 cwd。
4. 默认工作区：`~/rally`（设置可改），沿用原型的 `notes/ reports/ repo/` 结构。
5. 项目指令：worker 按自己的 cwd 加载 `AGENTS.md`、`.rally/`（skills、mcp、extensions）。主 agent **不**自动加载项目 `AGENTS.md`，需要时用只读工具读取（同 dsh：主 session 不读 AGENTS.md）。
6. 切换项目不影响进行中任务，只影响之后的派发默认值；任务卡显示所属项目。
7. Pi 会话存储改为按角色与任务分目录（`~/.rally/agent/sessions/main/`、`sessions/tasks/<taskId>/`），不用 Pi 默认的 `sessions/<encoded-cwd>/`。
8. 待议（第 6 轮）：首次打开带 `.rally/` 扩展的项目是否需要"信任此项目"确认（Pi 有 `trust-manager`）。

### Q6 改写/只读由谁定，调研产出写在哪

- 选项：派发时声明／全部按改写处理／首次写入时加锁
- **【已定】派发时声明**：主 agent 派发时声明 `mode` 与 `scope`，用户在外门审阅时可改。只读任务的 `write/edit` 只能写到自己的产出目录，scope 通常为空、可并行；shell 不拦截，只记录访问痕迹。

派生默认值：

1. **每个任务都有产出目录**：`<默认工作区>/outputs/<taskId>-<slug>/`，用户可直接浏览。改写任务的主要成果是 cwd 里的改动，截图、日志等附带产物也放这里。Rally 内部状态（会话、事件、审计）另放 `~/.rally/`，不混在一起。
2. 只读任务调用 `write/edit/file_delete` 写产出目录以外的路径 → 工具直接报错，提示"只读任务不能写项目目录；需要改动请汇报 blocked 说明原因"。
3. 升级路径：只读任务需要改写时，汇报 `blocked`，主 agent 用 `task_resume` 把它改成 `mode=write` 续接（重新排队拿名额，补填 `scope`，并按任务的外门设置走审批）。
4. 只读任务仍有 `bash/powershell`（clone、curl、跑分析脚本都需要）。提示词要求只读任务不得通过 shell 改动项目目录；若访问痕迹发现只读任务对项目目录有写入，记录为告警（同 D15"记录不阻断"）。
5. 只读任务与改写任务都只受名额约束；`scope` 交叉只警告不排队（见 Q2）。

### Q7 对已结束任务追加要求

- 选项：支持续接／只新建
- **【已定】支持续接**：提供 `task_resume`，由主 agent 判断续接原任务（同一 worker 会话、保留上下文，记为第 N 次运行）还是新建。规则：同一目标或同一批文件 → 续接，新目标 → 新建。

派生默认值：

1. `task_resume(taskId, quotes, note?, mode?)`，原则与派发相同：原话＋短备注。
2. 数据模型：任务含 `runs: Run[]`（对应 dsh `Assignment`），每次运行记录 `id/startedAt/endedAt/endReason/report`；任务状态由最新一次运行加未决问题推导。
3. 续接重新入队：要名额；补填 `scope`（如改写）。依赖不再检查（首次运行时已满足）。审批规则与派发相同，按该任务的自动批准设置（"用户侧只有一个确认点"）。
4. worker 会话：重新打开同一个 Pi 会话 JSONL，追加一条"追加要求（第 N 次运行）"消息。D2 中的"完成即归档"＝释放内存里的 `AgentSession`，JSONL 保留；v1 不自动清理。
5. 任何终态（完成/失败/取消/无需处理）都可续接；因为续接必须引用用户原话，所以它总是由用户发起。
6. 主 agent 判断补充：原 worker 会话已接近压缩阈值时，倾向新建任务，并以原任务作为上游依赖（结果自动注入，见第 3 轮）。

### Q8 worker 提问由谁回答

- 选项：有原话依据才代答／一律转用户（dsh 式）／主 agent 自主判断
- **【已定】有原话依据才代答**：主 agent 只能引用对话里已有的用户原话作答，答复必须带消息 ID、由系统逐字附上；找不到依据就原样转给用户，用户回答后自动回传 worker。worker 等待期间可以继续做不受影响的部分。

派生默认值：

1. worker 提问：`task_report({ state, question, options? })`。`options` 为 2–4 个候选答案，可选，UI 渲染为按钮并另附自由输入。同一任务同时只有一个未决问题，新问题覆盖旧问题（dsh `Attention`）。
2. 主 agent 代答：`task_answer(taskId, questionId, quotes: messageId[], note?)`。`quotes` 至少 1 条，**没有原话依据时工具层直接拒绝**。worker 收到的内容是"用户此前说过：〈原话〉（主 agent 备注：…）"。
3. 转给用户：主对话出现"需处理"卡片，问题文本由系统**逐字复制** worker 的原问题，主 agent 不得改写（dsh `handoff-orchestrator.md`：copy question exactly）。用户点选项按钮时系统直接回传，不经模型，并给主 agent 发一条不唤醒的通知；用户在输入框打字回答时，由主 agent 调 `task_answer` 引用这条新消息转交。
4. worker 仍可推进时，以 `state=progress` 带问题汇报，继续做不依赖答案的部分，任务同时显示"需处理"。完全卡住时用 `state=blocked` 带问题，结束本轮、释放名额；任务保持打开，`scope` 只是事实，不构成占用。
5. 问题生命周期：worker 显式清除、任务结束，或用户/主 agent 回答后关闭；同一问题重复提交只算一次。
6. **推及内门（待确认）**：worker 的不可逆动作上报主 agent 后，主 agent 放行同样必须引用用户原话作依据（如用户说过"把 dist 清掉"）；没有依据就上升给用户。改造计划 6.5 的 `gate_decided.basis` 统一为被引用的消息 ID。

## 第 3 轮 · 任务编排与会话（2026-11-08）

### Q9 依赖任务如何拿到上游成果、上游失败怎么办

- 选项：自动注入＋失败唤醒／主 agent 中转（不预声明依赖）／自动注入＋级联取消
- **【已定】自动注入＋失败唤醒**：B 启动时，系统把 A 的最终汇报（摘要、产出文件清单、改动文件清单）附进 B 的首条消息，B 还可用 `task_read` 读 A 的完整汇报。A 失败或取消时，B 保持排队，并唤醒主 agent 决定（取消 B／改依赖／续接 A）。

派生默认值：

1. `dependsOn` 只允许指向已存在的任务，派发时检查环；依赖全部"完成"才放行，任一上游非完成终态（失败/取消/无需处理）都触发唤醒。
2. 注入内容：每个上游一段，包含任务卡、汇报摘要（≤600 字）、产出目录、改动文件清单（来自访问痕迹，见 Q10）。上游很多时只给卡片和 `task_read` 指针。
3. 上游非完成终态时，下游状态变为 `queued(waiting: dependency_failed)`，UI 文案"排队中 · 上游 T-1042 失败，等待处理"。主 agent 的处理工具：`task_cancel`、`task_update_deps`、`task_resume`（续接上游）。主 agent 处理这件事不需要用户原话（它没有替用户做产品决定）；但如果处理方式会改变用户原话的意图（例如放弃 B），应先问用户。
4. worker 的 `task_read` 只能读**本任务的上游任务**的汇报和产出，不能读无关任务（dsh：Executor 只能读自己的 Ticket）。

### Q10 worker 汇报"完成"后任务是否就完成

- 选项：自证＋主 agent 核对证据（我的推荐）／worker 说完成就完成／自动派审查任务／用户验收才算完成
- **【已定】worker 说完成就完成**：任务完成以 worker 的 `ready` 为准，主 agent 只转述。

派生默认值：

1. 状态机：worker 汇报 `ready` → 任务立即进入终态 `done`，没有"待验收"中间态。
2. **证据由系统补齐，不靠 worker 自证**：完成卡片上的"改动文件、产出文件、执行过的命令及退出码"由系统从访问痕迹和工具事件自动汇总，worker 只写摘要。用户不用额外操作就能看到做了什么，主 agent 也不承担核查。
3. worker 提示词仍要求诚实：没跑过的检查不能说跑过，未完成的部分必须写明（dsh `work.md`："An incomplete draft is blocked"）。这是汇报规范，不是验收关卡。
4. 主 agent 转述时不加"已验证"之类它没做过的判断（沿用改造计划 4.1"不夸大"）。

### Q11 "新对话"与进行中任务

- 选项：单活对话＋历史只读／多对话可切换／永续单对话

### Q14 长命令与常驻进程

- 选项：自动转后台＋服务登记／前台＋超时／只前台、无常驻服务
- **【已定】自动转后台＋服务登记**：命令超过约 30 秒自动转为后台作业，worker 立刻拿回控制权，作业结束自动唤醒 worker；dev server 等常驻进程以"服务"登记在右栏，标注所属任务和端口，任务结束后继续运行，直到用户关闭或退出 Rally。

派生默认值：

1. **后台作业（job）**：覆盖 Pi 的 `bash/powershell` 工具。命令前台运行超过 30 秒（可设）就把当前输出与 `jobId` 返回给模型，提示"已转后台，完成后会通知你，不要轮询"；进程继续运行。作业结束后向该 worker 投递一条"作业完成"消息：worker 空闲时唤醒它，忙时 steer 进当前轮。dsh 用 5 秒；Rally 取 30 秒，减少短命令的打断。
2. 配套工具：`job_output(jobId, tail?)` 读输出（不阻塞等待）、`job_kill(jobId)`。不提供 `job_wait`，禁止 sleep 轮询（同 dsh `noWait` 守卫：拒绝 `sleep`、超长 timeout）。
3. 任务与作业：worker 结束一轮时若仍有作业在跑，任务保持"进行中"并继续占名额，作业结束唤醒同一 worker（dsh"Background work and worker slots"）。作业运行期间不算卡死（Q12 第 1 条）。
4. **服务（service）**：worker 用 `service_start({ command, cwd, port?, name })` 显式启动常驻进程。它不属于作业，不唤醒 worker、不占名额。登记信息含所属任务、命令、cwd、端口、PID、启动时间，在右栏"本地服务"列表展示，可打开预览或停止。
5. 服务生命周期：任务结束后继续运行；用户在右栏停止、该任务续接时 worker 重启它、或 Rally 退出时，用 taskkill 杀进程树。端口来自 `port` 参数或输出里的 `localhost:\d+`（尽力识别）。
6. 任务终态时，未结束的作业被杀（不唤醒）；服务保留。

3. 写入：`memory_append(text, quotes)`，`quotes` 必须引用用户说"记住…"的那条消息。修改/删除可以由用户直接编辑文件，或说"忘掉…"，由主 agent 调 `memory_remove(entryId, quotes)`。
4. 记忆是 Rally 自己的状态，不是项目文件，主 agent 写记忆**不违反** Q1 的只读边界（只读边界针对项目与系统）。
5. 任务 agent 不读记忆。和当前任务相关的记忆条目（例如"这个项目用 pnpm"），主 agent 可以写进派发备注（≤30 词，属于"用户明确约束"）。

### Q24 内门：主 agent 能否替用户放行不可逆动作

- 选项：有原话依据才放行／一律问用户／主 agent 自行判断
- **【已定】有原话依据才放行**：与 worker 提问规则（Q8）一致。确认了第 2 轮 Q8 第 6 条。

派生默认值：

1. 内门请求必须带：动作、工具、cwd、影响范围（路径清单或对象）、可替代做法；缺项视为无效请求（沿用改造计划 6.5）。
2. 主 agent 放行：`gate_decide(gateId, "allow", quotes)`，引用的原话必须**覆盖该动作与范围**（"清一下 dist"不覆盖 `src/generated`）。拒绝或要求换做法不需要原话。找不到依据 → `gate_escalate` → 主对话出现"需确认"卡片，逐字展示 worker 的请求与影响范围，用户点"允许/拒绝"或打字（由主 agent 转交）。
3. 审计：`gate_decided{decision, actor: "main"|"user", basis: messageId[]}`。
4. 超时＝拒绝（沿用改造计划 6.5：内门 120 秒，上升给用户后 10 分钟）。worker 收到拒绝后换做法或汇报 `blocked`。
5. v1 内门的强制点（不靠 shell 字符串匹配）：`file_delete`（非 dry-run）、`git` 工具的破坏性子命令（`reset --hard`、丢弃改动的 `checkout/restore`、`clean`、`push --force`、`branch -D`、`stash drop/clear`）、用户标为"不可逆"的 MCP 工具。提示词要求不可逆动作只能走这些工具；shell 里的同类操作只做可见性记录（改造计划 D15）。
