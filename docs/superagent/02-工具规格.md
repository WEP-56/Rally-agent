## 1. 通用约定

1. **原话引用参数**（Q4/Q8/Q23/Q24）：凡标注"需原话"的工具都带
   ```ts
   quotes: { id: string; withProposal?: boolean }[]   // id 形如 "#1203"
   ```
   校验：至少 1 条；id 存在且 `role=user`；`withProposal` 只在该用户消息之前紧邻一条主 agent 消息时有效。不通过 → 报错 `QUOTE_INVALID`，并附错误原因。系统把引用冻结为 `Quote` 副本（01 §2.1）。
2. **"需原话"的范围**：主 agent 所有改变任务、替用户做决定、写记忆的工具。例外只有两个：`escalate` 和 `gate_decide(deny)`（01 §0 原则 1）。
3. **错误**：工具返回 `isError: true`，正文为 `CODE: 人话说明 + 怎么改`。错误码集中定义（参考 dsh `USER_ERRORS`），界面按码给出文案。
4. **输出截断**：文本输出超过 30,000 字符时保留头尾、中间省略，并给出读取剩余部分的办法（偏移量或作业 ID）。沿用 Pi 的截断工具函数。
5. **路径**：主 agent 的相对路径按"当前项目"解析；worker 的相对路径按任务 cwd 解析。所有路径先规范化（04 §2.3）再做判断。
6. **任务结束后**：该任务 worker 的任何工具调用都返回 `TASK_ENDED`（`tool_call` 钩子统一拦截）。
7. **幂等**：`task_dispatch` 以（排序后的引用 id＋标题）为幂等键，60 秒内重复调用返回同一任务；`task_report` 对完全相同的问题不重复开问题（Q8 派生 5）。

## 2. 主 agent 工具

### 2.1 只读侦察（Q1）

**`read` / `grep` / `find` / `ls`**：Pi 内置，原样使用。不限制读取范围（C3/C5：无权限系统）。

**`git_inspect`**
```ts
git_inspect({ cwd?: string, command: "status" | "log" | "diff" | "show" | "branch", args?: string[] })
→ { output: string, exitCode: number }
```
- 以参数数组调用 git（不经 shell），设置 `GIT_OPTIONAL_LOCKS=0`，避免 `status` 写索引锁。
- `branch` 只允许列出；带 `-d/-D/-m/-c` 等改动参数 → `READONLY_VIOLATION`。

**`web_search`**
```ts
web_search({ query: string, count?: number /* 默认 5，最多 10 */ })
→ { results: { title: string, url: string, snippet: string }[] }
```
搜索服务商可插拔，在设置里配置（Q19 派生 1，选型待定）。

**`fetch_page`**
```ts
fetch_page({ url: string, maxChars?: number /* 默认 20000 */, offset?: number })
→ { url: string, finalUrl: string, title: string, text: string /* Markdown */, truncated: boolean, nextOffset?: number }
```
HTTP 获取后抽取正文转 Markdown，不执行 JS。动态页面交给用户配置的浏览器类 MCP（Q19）。

**`github_read`**
```ts
github_read({ action: "issue_list" | "issue_view" | "pr_list" | "pr_view", repo?: string, number?: number, search?: string, state?: "open" | "closed" | "all" })
→ 精简 JSON（标题、状态、作者、正文前 4000 字、评论数、PR 检查结果摘要）
```
封装用户本机已登录的 `gh`；`repo` 默认取当前项目的 origin。

**`chat_search`**（Q11 派生 3）
```ts
chat_search({ query?: string, id?: string, aroundId?: string, before?: number, after?: number, limit?: number /* 默认 20 */ })
→ { messages: { id: string, role: "user" | "assistant", at: number, text: string }[], next?: string }
```
- 检索压缩前的完整对话（跨物理分段）。带 `id` 时返回该条全文；其余情况每条只返回 200 字预览。
- 只返回用户与主 agent 的消息，不返回中继和通知。用途是找到可以引用的 `#id`。

### 2.2 任务工具

**`task_dispatch`**（Q4/Q5/Q6/Q9）
```ts
task_dispatch({
  title: string,                 // ≤40 字符
  quotes: Quote[],               // 需原话
  note?: string,                 // ≤30 词（Intl.Segmenter 分词计数）；只写路由背景或用户明确约束
  cwd?: string,                  // 默认当前项目；未打开项目时为默认工作区
  mode: "write" | "readonly",
  dependsOn?: string[],
})
→ { taskId: string, status: string, approval: "pending" | "approved", queuedReason?: QueueReason, outputDir: string }
```
错误：`QUOTE_INVALID`、`CWD_NOT_FOUND`、`DEP_NOT_FOUND`、`DEP_CYCLE`、`TITLE_TOO_LONG`、`NOTE_TOO_LONG`。

**`task_approve`**（Q17）：用户用文字批准时调用。
```ts
task_approve({ taskId: string, quotes: Quote[] }) → { status: string }
```
只对 `approval=pending` 有效，否则报 `NOT_PENDING`。

**`task_update`**：修改尚未启动的任务。
```ts
task_update({ taskId: string, quotes: Quote[], title?: string, note?: string, cwd?: string, mode?: TaskMode, dependsOn?: string[] })
→ { status: string }
```
只对"待批准／排队中"的任务有效，否则报 `ALREADY_STARTED`，提示改用 `task_steer` 或 `task_resume`。

**`task_steer`**（01 §4.5）
```ts
task_steer({ taskId: string, quotes: Quote[], note?: string })
→ { delivery: "queued_with_first_message" | "steered" | "woke_worker" }
```
已结束的任务报 `TASK_ENDED`，提示改用 `task_resume`。

**`task_answer`**（Q8）
```ts
task_answer({ taskId: string, questionId: string, quotes: Quote[], note?: string })
→ { delivery: "steered" | "woke_worker" }
```
问题已被回答或已被替换 → 报 `QUESTION_STALE`。

**`task_resume`**（Q7）
```ts
task_resume({ taskId: string, quotes: Quote[], note?: string, mode?: TaskMode })
→ { runN: number, status: string, approval: "pending" | "approved" }
```
只对已结束或"中断"的任务有效；进行中的任务报 `TASK_ACTIVE`，提示用 `task_steer`。

**`task_cancel`**
```ts
task_cancel({ taskId: string, quotes: Quote[] })
→ { outcome: "cancelled", killedJobs: number, affected: { taskId: string, status: "dependency_failed" }[] }
```

**`task_read`**
```ts
task_read({ taskId?: string, view?: "board" | "card" | "report" | "runs" | "files" | "timeline", offset?: number, limit?: number })
```
| view | 内容 |
| --- | --- |
| `board`（无 taskId 时默认） | 所有未结束的任务＋最近 20 个已结束任务的卡片 |
| `card` | 标题、状态、cwd、mode、依赖、原话、备注、耗时、用量 |
| `report` | 最近一次汇报全文、未决问题、未决门 |
| `runs` | 历次运行与结束原因 |
| `files` | 访问痕迹：读过、写过、删过的文件，访问过的域名，作业与服务 |
| `timeline` | 最近 20 条工具调用的一行摘要。用于回答"做到哪了"（Q16 不做阶段名的替代）；**不提供 worker 完整对话**（Q3 派生 4） |

### 2.3 内门与上升（Q8/Q24）

**`gate_decide`**
```ts
gate_decide({ gateId: string, decision: "allow" | "deny", quotes?: Quote[], reason: string })
→ { decided: true }
```
- `allow` 必须带 `quotes`，且原话要覆盖该动作与范围。是否覆盖由模型判断，系统只校验引用存在、是用户原话，并把引用写进审计。
- 门已超时或已决定 → `GATE_STALE`。

**`escalate`**
```ts
escalate({ kind: "question" | "gate", taskId: string, id: string }) → { shown: true }
```
在主对话插入需处理卡片，内容由系统逐字取自 worker 的请求，主 agent 不能改写。

### 2.4 记忆（Q23）

```ts
memory_append({ text: string /* ≤300 字 */, quotes: Quote[] }) → { entryId: string }
memory_remove({ entryId: string, quotes: Quote[] }) → { removed: true }
```
- 存储为 `~/.rally/memory/MEMORY.md` 的条目，每条带 `<!-- id: M-12 -->` 标记，用户手动编辑时保留。
- 记忆超过约 2k tokens 时，`memory_append` 的返回值附带"请提醒用户精简"的提示。

## 3. 任务 agent 工具

### 3.1 文件：`read` `write` `edit` `grep` `find` `ls`

Pi 内置，worker 侧包两层：

1. **只读模式**（Q6）：`write`、`edit`、`file_delete` 的目标不在本任务 `outputDir` 内 → `READONLY_TASK`："只读任务不能写入此路径；需要改动请用 task_report(blocked) 说明"。
2. **读后被改检测**（Q2 派生 5）：会话记录每个文件最后一次被读到的 mtime 与哈希。`write`、`edit` 前发现文件已被他人改过 → `STALE_FILE`："文件在你读取后被修改，请重新读取"。新建文件不受此限。

### 3.2 命令与作业（Q14）

**`bash` / `powershell`**（覆盖 Pi 实现）
```ts
bash({ command: string, timeout?: number /* 秒，到时强杀；默认不限 */ })
→ 前台完成：{ exitCode: number, output: string, durationMs: number }
→ 转入后台：{ jobId: string, background: true, output: string /* 已有输出 */, note: string }
```
- 前台最多等 30 秒（设置项 `jobs.foregroundSeconds`），超过即转后台作业，进程继续运行。`note` 内容："已转为后台作业 J-3，结束后会通知你；继续其他工作或结束本轮，不要轮询。"
- 作业结束 → 系统向该 worker 投递 `job_done` 输入（`exitCode`＋输出尾部 200 行）：worker 空闲则唤醒，忙则 steer。
- 守卫（同 dsh `noWait`）：拒绝以 `sleep`／`Start-Sleep`／`timeout /t` 开头的命令（`NO_POLLING`）。
- 输出编码：子进程强制 UTF-8（改造计划 7.3）。

**`job_output`**
```ts
job_output({ jobId: string, tail?: number /* 行，默认 200 */ })
→ { status: "running" | "exited" | "killed", exitCode?: number, output: string, durationMs: number }
```
立即返回，不等待（没有 `job_wait`）。

**`job_kill`**：`job_kill({ jobId }) → { killed: true }`，杀进程树（04 §5.3）。

### 3.3 服务（Q14）

```ts
service_start({ name: string, command: string, cwd?: string, port?: number, readyPattern?: string /* 输出正则 */, env?: Record<string, string> })
→ { serviceId: string, pid: number, port?: number, url?: string, ready: boolean, output: string }
service_stop({ serviceId: string }) → { stopped: true }
service_status({ serviceId: string, tail?: number }) → { status: "running" | "exited" | "stopped", port?: number, output: string }
```
- `service_start` 最多等 30 秒：直到端口开始监听或输出匹配 `readyPattern`，然后返回 `ready`。
- 端口取 `port` 参数，没有时从输出里识别 `localhost:\d+` / `127.0.0.1:\d+`（尽力而为）。
- 服务不唤醒 worker、不占名额；生命周期见 04 §5.2。

### 3.4 受控删除：`file_delete`（C5）

```ts
file_delete({ paths: string[], recursive?: boolean, dryRun?: boolean /* 默认 true */ })
→ dryRun：{ matched: number, totalBytes: number, preview: string[] /* ≤50 */, uncommitted: string[], outsideCwd: string[] }
→ 实删：{ deleted: number, failed: { path: string, error: string }[] }
```
- 实删（`dryRun=false`）默认走内门（01 §4.4）。门请求的影响范围直接取 dry-run 的结果。
- **不过门的例外**（保持"门极少"）：目标全部位于本任务 `outputDir` 内，或全部是本任务新建的文件（访问痕迹里有 `created` 标记）。
- 只读任务只能删 `outputDir` 内的文件。

### 3.5 `git`

```ts
git({ args: string[], cwd?: string }) → { exitCode: number, output: string }
```
以参数数组调用 git（结构化，不是 shell 字符串匹配）。按子命令和参数分档，清单放在配置文件里（D14）：

| 档 | 子命令/参数 |
| --- | --- |
| 不可逆 → 内门 | `reset --hard`；`checkout`／`restore` 丢弃工作区改动（`checkout -- <path>`、`checkout .`、不带 `--staged` 的 `restore`、`checkout -f`、`switch --discard-changes`／`-f`）；`clean`；`push --force`／`--force-with-lease`／`+refspec`／`--delete`／`--mirror`；`branch -D`；`stash drop`／`clear`；`reflog expire`；`gc --prune` |
| 有对外代价 → 提示不阻断＋审计 | 普通 `push`、`push --tags` |
| 可逆 | 其余（`status/log/diff/add/commit/branch/switch/merge/rebase/stash push|pop/fetch/pull/tag`…） |

- 提示词规定：commit 与 push 只在原话要求时做（Q21 派生 3）。
- worker 通过 shell 执行同类 git 命令不会被拦截，只记录可见性（改造计划 D15）。

### 3.6 联网（Q19）

`web_search`、`fetch_page`：同 §2.1。

```ts
http_request({ method: "GET" | "POST" | "PUT" | "PATCH" | "DELETE" | "HEAD", url: string, headers?: Record<string, string>, body?: string, timeoutMs?: number /* 默认 30000 */ })
→ { status: number, headers: Record<string, string>, body: string /* ≤20000 字 */, truncated: boolean }
```
网络请求属可逆档，不设门（C5）；非 GET 请求在访问痕迹里记录方法。

### 3.7 GitHub（Q19）

```ts
github({ action: "issue_list" | "issue_view" | "issue_create" | "issue_comment" | "pr_list" | "pr_view" | "pr_create" | "pr_comment",
  repo?: string, number?: number, title?: string, body?: string, base?: string, head?: string, draft?: boolean, search?: string })
```
- `*_create`、`*_comment` 属"有对外代价"：执行后在右栏显示提示条并写审计，不阻断（C5 第二档）。
- 需要在 GitHub 上留言、开 PR，以原话要求为前提（提示词规则）。

### 3.8 MCP（Q19）

- 沿用 Pi MCP：配置文件为 `~/.rally/agent/mcp.json` 与项目内 `.rally/mcp.json`（项目内的需先信任项目，附 A3）。
- 工具名形如 `mcp__<server>__<tool>`，只注入任务 agent。
- 档位：默认可逆。用户在设置页"MCP"分区可为单个工具标"有对外代价"或"不可逆"，保存在 `settings.json` 的 `mcpTiers`；标为不可逆的工具调用走内门。

### 3.9 汇报：`task_report`

```ts
task_report({
  state: "progress" | "ready" | "blocked" | "failed" | "dropped",
  summary: string,                 // 必填；建议 ≤1500 字；中继时截到 600 字
  question?: string | null,        // 省略＝保持未决问题；null＝清除；字符串＝新建或替换
  options?: string[],              // 2–4 个，每个 ≤40 字；仅在 question 为字符串时有效
})
→ { recorded: true, notifiedMain: boolean, taskEnded: boolean }
```
- 语义见 01 §2.3。`ready`、`failed`、`dropped` 会清除未决问题。
- 摘要的写法规则在提示词里（已完成与未完成分开写，不虚报检查）；改动文件、产出由系统补齐（Q10 派生 2），**不需要**在摘要里罗列。

### 3.10 读取：`task_read`（受限）

同 §2.2，但只能读：本任务（`card/report/files/runs`，以及 `services`：本任务启动的服务），以及本任务 `dependsOn` 中上游任务的 `card/report/files`（Q9 派生 4）。越界 → `NOT_VISIBLE`。

### 3.11 任务 agent **没有**的工具

子 agent／`task_dispatch`（Q15）、`chat_search`、记忆工具（Q23）、`escalate`／向用户提问的工具（问题只能走 `task_report`）、交互式终端（Q20：终端归用户）。

## 4. 门控分档与审计（C5）

| 档 | v1 落点 | 行为 |
| --- | --- | --- |
| 可逆 | 其余全部 | 不设门，只记访问痕迹 |
| 有对外代价 | `git push`、`github` 的 create/comment、标为该档的 MCP 工具 | 照常执行；右栏提示条＋审计一行 |
| 不可逆 | `file_delete` 实删（例外见 §3.4）、`git` 破坏性子命令、标为该档的 MCP 工具 | 内门：主 agent 凭原话放行，否则上升用户（01 §4.4） |

## 5. 投影信封与访问痕迹（取代改造计划 3.3）

```ts
interface ToolResultEnvelope {
  toolCallId: string;
  agent: "main" | "worker";
  taskId?: string;
  runId?: string;
  kind: "cmd" | "job" | "service" | "read" | "write" | "edit" | "delete" | "search" | "web" | "git" | "github" | "mcp" | "task" | "gate" | "memory" | "think";
  title: string;                 // 卡片标题，如"运行 npm test"
  target: string;                // 命令／路径／URL／任务 ID
  status: "running" | "ok" | "error" | "blocked" | "backgrounded";
  output?: string;               // 折叠展示的原文（已截断）
  diff?: { add?: string[]; del?: string[]; ctx?: string[] };   // 来自 edit 的 EditToolDetails
  exitCode?: number;
  durationMs?: number;
  riskTier: "reversible" | "external" | "irreversible";
  access?: { kind: "fs_read" | "fs_write" | "fs_delete" | "net"; target: string; created?: boolean; method?: string }[];
}
```

访问痕迹提取规则：

| 工具 | 记录 |
| --- | --- |
| `read` `grep` `find` `ls` `git_inspect` | `fs_read`（路径或搜索根目录） |
| `write` `edit` | `fs_write`；目标原本不存在时标 `created` |
| `file_delete` 实删 | `fs_delete`（逐个路径） |
| `git` | 按子命令记 `fs_read`／`fs_write`；`fetch/pull/push` 另记 `net`（remote 主机名） |
| `web_search` `fetch_page` `http_request` `github*` | `net`（域名；`http_request` 非 GET 记 `method`） |
| `bash` `powershell` | 只记 cwd 与命令，不解析命令（不做 shell 字符串匹配）；界面标注"shell 访问未知" |
| MCP 工具 | `net` 或服务器名 |

完成卡片上的"改动文件、产出、命令与退出码"（Q10 派生 2）就是按任务聚合这张表的结果。

## 6. 模型面预算与测试

- 参照 dsh `tests/model-surface.spec.ts`：用一个测试检查每个角色看到的全部模型面文本（系统提示词＋工具描述＋固定消息模板），断言：
  1. 提示词里提到的每个工具名都真实存在于该角色的工具集；
  2. 每个角色的总长度不超过预算（建议主 agent ≤ 6k tokens，任务 agent 在 Pi 基础提示词之外 ≤ 4k tokens）；
  3. 错误码都有界面文案。
- 工具描述只写"什么时候用、参数含义、返回什么"，规则放在提示词里，避免两处重复、互相矛盾。
