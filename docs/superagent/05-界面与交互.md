# 05 界面与交互

- 依据：[00-问答记录.md](00-问答记录.md) Q5/Q11/Q12/Q13/Q16/Q17/Q18/Q20/Q22/Q23、附 A4/A6，`example/rally-ai-agent-ui-design`（**只作风格参考**，Q16 用户补充）

## 1. 窗口结构

```text
┌ 标题栏：菜单 · 保留拖拽空白区域 · 窗口按钮 ───────────────────────────────┐
│ 左栏：主对话（唯一、永续）        │ 右栏：标签页（只读）                     │
│  头部：名字 · 在线/思考中 ·        │  [工位] [T-1045] [浏览器] [终端] [+]      │
│        N 个任务进行中 · 整理上下文 │                                          │
│  消息流（完整历史，向上懒加载）    │                                          │
│  输入框：附件 · @任务 · 模型 ·     │                                          │
│        需要批准/自动批准 · 发送/停止│                                          │
└───────────────────────────────────┴──────────────────────────────────────────┘
```

- 标题栏：Electron 无边框窗口＋Windows `titleBarOverlay`（原生最小化/最大化/关闭），菜单沿用原型 `TitleBar`。
- 标题栏不增加项目或工作区入口，保留拖拽空白区域（Q5，2026-11-09 用户修订）。项目与工作区入口只在既有设置页。
- 双栏比例可拖动、右栏可收起（原型 `App.tsx` 已有）。

## 2. 主对话（左栏）

### 2.1 消息类型

| 类型 | 何时出现 | 可交互 |
| --- | --- | --- |
| 用户气泡 | 用户发送 | 否 |
| 主 agent 发言 | agent loop 内每条 assistant 消息均展示；按原内容顺序排列文字、thinking 和工具调用（02 §5） | 思考与工具各自默认收起，可展开 |
| 系统行 | 中继唤醒主 agent 时，标记触发原因，如"T-1045 已完成""T-1046 有问题等待处理" | 点击打开对应任务页 |
| 派发卡 | `task_dispatch`／`task_resume` 之后 | 待批准时有"批准／取消"按钮（Q17） |
| 问题卡 | 主 agent `escalate` 一个问题（Q8） | 选项按钮；也可以直接在输入框回答 |
| 确认卡 | 主 agent `escalate` 一个内门请求（Q24） | "允许／拒绝"按钮，显示剩余时间 |
| 上下文分隔条 | 一次压缩完成（Q11） | 否；文案"上文已整理" |

主对话里的卡片按钮属于主对话，不违反 Q18（00 第 5 轮 Q18 派生 2，可推翻）。

### 2.2 派发卡

```text
┌ T-1045 · landing 页响应式适配                    [进行中 · 4 分钟] ┐
│ 改写 · C:\proj                         依赖：无                     │
│ ▸ 原话（2 条）  ▸ 备注：设计稿导出图在 docs/design/ 下              │
│ （待批准时）                                     [取消]  [批准]     │
└─────────────────────────────────────────────────────────────────────┘
```

- 状态为**实时**的粗略状态（01 §3），耗时由界面本地每秒计算，不产生事件（改造计划 5.5）。
- 点击卡片 → 右栏打开该任务的标签页。
- 没有编辑表单；要改 cwd、mode、备注，用户在输入框里说（Q17 派生 3）。

### 2.3 问题卡与确认卡

问题卡：

```text
┌ T-1046 需要你决定                                                  ┐
│ 旧的 /api/v1/price 还有调用方吗？保留兼容层还是直接删？             │
│   [保留兼容层]  [直接删除]      或直接在下方输入你的回答              │
└─────────────────────────────────────────────────────────────────────┘
```

确认卡：

```text
┌ T-1047 请求不可逆操作                                    剩余 9:41 ┐
│ 删除文件 · C:\proj                                                  │
│ dist/（412 个文件）、coverage/（37 个文件）                          │
│ 可替代做法：只删 dist/                                               │
│                                              [拒绝]  [允许]         │
└─────────────────────────────────────────────────────────────────────┘
```

- 卡片正文**逐字**取自 worker 的请求，主 agent 不能改写（Q8 派生 3）。
- 处理后卡片折叠为一行结果："已允许（你，14:03）""主 agent 依据 #1190 代答"。

### 2.4 输入框

| 控件 | 行为 |
| --- | --- |
| 附件 | 附件随消息成为原话的一部分，被引用时一起送达 worker（Q4 派生 2） |
| `@` | 插入任务引用 `@T-1045`（纯文本，便于主 agent 定位任务） |
| 模型下拉 | 快速切换"主 agent 模型"这一全局设置（Q22） |
| 需要批准／自动批准 | 全局开关，默认"需要批准"（Q17） |
| 发送／停止 | 停止只中断主 agent 当前这一轮，**不影响任务**（Q18 派生 3） |

主 agent 忙时照样可以发送，消息以 steer 并入当前轮（附 A9），界面显示"已插入"。

### 2.5 头部

- 名字（人设，附 A4）、状态（在线／思考中）、"N 个任务进行中"。
- "整理上下文"按钮代替原型的"新对话"（Q11 派生 6）：手动触发一次压缩。

## 3. 右栏（只读，Q18）

### 3.1 工位

- 名片：名字、性格、记忆路径、主 agent 模型 / 任务 agent 模型、工作方式（原型 `Workstation` 风格，内容来自设置）。
- 统计条：今日任务、进行中、需处理、已完成，外加**今日用量**（token／估算费用，Q12 派生 2）。
- 筛选：全部、进行中、排队中、需处理、已完成；排序：最新／最早。
- 任务行：标题、粗略状态（01 §3）、编号、所属项目、耗时或完成时刻。**没有进度条、没有技能标签**（Q13/Q16）。

### 3.2 任务页

| 区块 | 内容 |
| --- | --- |
| 头部 | 标题、状态、编号、cwd、mode、模型、耗时、用量 |
| 简报 | 原话（逐字）＋备注＋上游任务 |
| 时间线 | 按运行分段（第 1 次、第 2 次…）；worker 每条 assistant 叙述、默认收起的 thinking 与工具卡按内容顺序展示；汇报、问题与回答、门与决定、作业与服务事件 |
| 访问痕迹 | 读过的文件、写过的文件、删过的文件、访问的域名、作业、服务（02 §5）；shell 访问标注"未知" |
| 底部 | 只读说明＋"在主对话中提及"（把 `@T-1045` 填入输入框）＋"在此目录打开终端" |

没有输入框，也没有停止、重试、续接按钮（Q18）。

2026-11-09 实现增量：主/任务页共用有序 assistant 内容组件；每条消息的 thinking 作为独立折叠项，与工具组同级，支持流式更新和重启恢复。只呈现供应商返回的可读思考，不展示签名/不透明数据，不生成缺失的思考。worker 详细内容只送用户界面，不附到 task_read。按运行分隔标题、问题/门/作业等完整事件时间线仍按 TODO 补齐；旧 Pi JSONL 未做补录。

### 3.3 浏览器（Q20）

- Electron `WebContentsView` 内嵌：地址栏、后退、前进、刷新；多标签沿用右栏标签体系。
- 起始页 `rally://start`：列出本地服务（所属任务、名称、端口、状态），点击即打开预览；每个服务有"停止"按钮（04 §5.2 的待定细节）。
- 隔离：独立 session partition，`nodeIntegration: false`，`contextIsolation: true`，`sandbox: true`，页面拿不到任何 Rally IPC。
- agent 不操作这个浏览器；浏览器自动化由用户配置 MCP（Q19）。

实施（2026-11-10）：工位和起始页使用真实服务列表及用户停止 IPC；浏览器已从临时 iframe 迁移为每标签独立 WebContentsView，共用独立持久 partition `persist:rally-browser`。远端页无 preload、无 Node/Rally IPC，导航/标题/加载/前后退读取 Chromium 实际状态；支持 HTTP/HTTPS、本地服务、系统浏览器打开、失败重试。地址栏和标签沿用原型 token。设置、命令面板、菜单、抽屉、拖动及右栏隐藏时隐藏原生视图，标签切换保留页面，关闭/宿主重载/退出释放子内容。

开源选型核实（Q20 派生 3，2026-11-10）：参考并适配 [electron-browser-shell 的 tabs.js](https://github.com/samuelmaddock/electron-browser-shell/blob/master/packages/shell/browser/tabs.js) 中 WebContentsView 创建/挂载/切换/布局/释放流程；[根许可证 MIT](https://github.com/samuelmaddock/electron-browser-shell/blob/master/LICENSE)，版权声明已保存在 `THIRD_PARTY_NOTICES/electron-browser-shell-LICENSE.txt` 并纳入打包文件。仅使用 shell 页签生命周期模式，没有引入其扩展包；不能把同仓库 electron-chrome-extensions 子包视为相同许可证。Electron API 以当前 [WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)、[资源释放](https://www.electronjs.org/docs/latest/api/base-window#resource-management) 和 [导航历史](https://www.electronjs.org/docs/latest/tutorial/navigation-history) 文档核对。终端开源集成选型及实测结果见 §6。

实现边界：普通 HTTP/HTTPS 新窗口链接转为右栏新标签，不保留 window.opener 或原生弹窗关系；新窗口 POST、下载和摄像头/定位等权限暂给出系统浏览器入口提示，不宣称 OAuth/复杂弹窗全兼容。本地页面允许其本地网络权限，外部站点不因此获得内网权限。11 项 Electron 替身专项及 4 项 IPC 生命周期测试通过；实际 Electron 预览、遮挡/焦点、窗口缩放、浅深色和关闭体验待用户验收，开发侧未启动 UI。

### 3.4 终端（Q20）

- xterm.js＋node-pty（ConPTY）。默认 shell 为 PowerShell 7，没有则用 Windows PowerShell 5.1；初始 cwd 为主对话默认工作区，或从任务页打开时为任务 cwd。
- 可开多个终端标签；关闭标签即结束对应进程树。
- 终端**归用户**：agent 不读不写（Q20 派生 1）。

实施（2026-11-10）：TerminalView 已替换模拟命令集，直接使用 xterm 及 fit/web-links/search/unicode11 插件。宿主选择已安装的 PowerShell 7，未找到则 Windows PowerShell；默认 cwd 来自主对话工作区，任务页新增“在此目录打开终端”，主进程按任务 ID 取真实 cwd。标题明确显示初始目录，不把 shell 内 cd 猜成实时 cwd。Ctrl+F 查找、Ctrl+Shift+C/V 复制粘贴，Ctrl+点击 HTTP/HTTPS 链接交给系统浏览器；Ctrl+C 仍发往 shell。

独立 terminal-host 承载 node-pty；主进程先取得宿主 PID/创建时间再启动 shell，关闭按核验后的进程树终止，启动取消立即中断等待。shell 退出后仍保留宿主根，清理后才能结束标签；正常退出、UI 重载/崩溃及应用退出均清理。主进程强杀导致 IPC 断连时宿主自清理整树。失败保留标签并显示错误以便重试。未持久保存终端进程或恢复终端历史，主动脱离父子关系/权限改变的进程不保证回收。

输入输出只经用户所属窗口主 frame 的声明 IPC，未提供模型工具，不进入任务事件/审计/会话。xterm 写入回调按序号确认，宿主高低水位暂停/恢复，防止快速输出无限积压；最多 16 个终端、每页 5000 行回滚。设置页切换改为隐藏主面板，终端与浏览器实例保持；退出页签才销毁。采用原型 bg-term、fg、accent、字号与间距。真实进程和 IPC 离线验证通过，实际键盘/粘贴/焦点/浅深色/窗口行为由用户验收。

## 4. 系统通知（附 A6）

| --- | --- |

## 6. 开源复用选型（Q20）

2026-11-10 核实与实测：锁定 @xterm/xterm 6.0.0、fit 0.11.0、web-links 0.12.0、search 0.16.0、unicode11 0.9.0、node-pty 1.1.0；原包 LICENSE 已核对，版权说明随 THIRD_PARTY_NOTICES 打包。参考适配 [Tabby session.ts](https://github.com/Eugeny/tabby/blob/master/tabby-local/src/session.ts) 的 PTY 会话/尺寸/环境/生命周期及 ConPTY DLL 回退；[Tabby MIT](https://github.com/Eugeny/tabby/blob/master/LICENSE) 声明已保留。流控采用 [xterm.js 官方指南](https://xtermjs.org/docs/guides/flowcontrol/) 的高低水位＋写入确认思路。

本机 Windows x64 已通过真实 node-pty/Powershell 及仓库 Electron Node 模式验证；构建文件与 ASAR 内宿主都可直接加载包内预编译模块，不需要新增 rebuild。原生库及辅助文件通过 `node_modules/node-pty/**/*` 整包解包；Windows 10 2004+ 优先 bundled ConPTY DLL，加载失败回退系统 ConPTY，低版本交给 node-pty 系统选择。本机不是旧版 Windows，低版本回退与 NSIS 实际安装未验收。安装没有执行依赖生命周期脚本。
