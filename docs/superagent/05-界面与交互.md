# 05 界面与交互

- 依据：[00-问答记录.md](00-问答记录.md) Q5/Q11/Q12/Q13/Q16/Q17/Q18/Q20/Q22/Q23、附 A4/A6，`example/rally-ai-agent-ui-design`（**只作风格参考**，Q16 用户补充）
- 原则：功能与字段以问答结论为准；原型决定"长什么样"，不决定"有什么"。右栏只读，一切任务操作都在主对话里完成（Q18）。

## 1. 窗口结构

```text
┌ 标题栏：菜单 · 当前项目 ▾（最近项目 / 打开文件夹…） · 窗口按钮 ─────────────┐
│ 左栏：主对话（唯一、永续）        │ 右栏：标签页（只读）                     │
│  头部：名字 · 在线/思考中 ·        │  [工位] [T-1045] [浏览器] [终端] [+]      │
│        N 个任务进行中 · 整理上下文 │                                          │
│  消息流（完整历史，向上懒加载）    │                                          │
│  输入框：附件 · @任务 · 模型 ·     │                                          │
│        需要批准/自动批准 · 发送/停止│                                          │
└───────────────────────────────────┴──────────────────────────────────────────┘
```

- 标题栏：Electron 无边框窗口＋Windows `titleBarOverlay`（原生最小化/最大化/关闭），菜单沿用原型 `TitleBar`。
- "当前项目"放在标题栏（Q5）：切换只影响之后派发的默认目录，不新开对话。
- 双栏比例可拖动、右栏可收起（原型 `App.tsx` 已有）。

## 2. 主对话（左栏）

### 2.1 消息类型

| 类型 | 何时出现 | 可交互 |
| --- | --- | --- |
| 用户气泡 | 用户发送 | 否 |
| 主 agent 发言 | 每轮；只读工具调用以折叠的工具卡展示（02 §5） | 展开/收起 |
| 系统行 | 中继唤醒主 agent 时，标记触发原因，如"T-1045 已完成""T-1046 有问题等待处理" | 点击打开对应任务页 |
| 派发卡 | `task_dispatch`／`task_resume` 之后 | 待批准时有"批准／取消"按钮（Q17） |
| 问题卡 | 主 agent `escalate` 一个问题（Q8） | 选项按钮；也可以直接在输入框回答 |
| 确认卡 | 主 agent `escalate` 一个内门请求（Q24） | "允许／拒绝"按钮，显示剩余时间 |
| 上下文分隔条 | 一次压缩完成（Q11） | 否；文案"上文已整理" |

主对话里的卡片按钮属于主对话，不违反 Q18（00 第 5 轮 Q18 派生 2，可推翻）。

### 2.2 派发卡

```text
┌ T-1045 · landing 页响应式适配                    [进行中 · 4 分钟] ┐
│ 改写 · C:\proj                         依赖：无                     │
│ ▸ 原话（2 条）  ▸ 备注：设计稿导出图在 docs/design/ 下              │
│ （待批准时）                                     [取消]  [批准]     │
└─────────────────────────────────────────────────────────────────────┘
```

- 状态为**实时**的粗略状态（01 §3），耗时由界面本地每秒计算，不产生事件（改造计划 5.5）。
- 点击卡片 → 右栏打开该任务的标签页。
- 没有编辑表单；要改 cwd、mode、备注，用户在输入框里说（Q17 派生 3）。

### 2.3 问题卡与确认卡

问题卡：

```text
┌ T-1046 需要你决定                                                  ┐
│ 旧的 /api/v1/price 还有调用方吗？保留兼容层还是直接删？             │
│   [保留兼容层]  [直接删除]      或直接在下方输入你的回答              │
└─────────────────────────────────────────────────────────────────────┘
```

确认卡：

```text
┌ T-1047 请求不可逆操作                                    剩余 9:41 ┐
│ 删除文件 · C:\proj                                                  │
│ dist/（412 个文件）、coverage/（37 个文件）                          │
│ 可替代做法：只删 dist/                                               │
│                                              [拒绝]  [允许]         │
└─────────────────────────────────────────────────────────────────────┘
```

- 卡片正文**逐字**取自 worker 的请求，主 agent 不能改写（Q8 派生 3）。
- 处理后卡片折叠为一行结果："已允许（你，14:03）""主 agent 依据 #1190 代答"。

### 2.4 输入框

| 控件 | 行为 |
| --- | --- |
| 附件 | 附件随消息成为原话的一部分，被引用时一起送达 worker（Q4 派生 2） |
| `@` | 插入任务引用 `@T-1045`（纯文本，便于主 agent 定位任务） |
| 模型下拉 | 快速切换"主 agent 模型"这一全局设置（Q22） |
| 需要批准／自动批准 | 全局开关，默认"需要批准"（Q17） |
| 发送／停止 | 停止只中断主 agent 当前这一轮，**不影响任务**（Q18 派生 3） |

主 agent 忙时照样可以发送，消息以 steer 并入当前轮（附 A9），界面显示"已插入"。

### 2.5 头部

- 名字（人设，附 A4）、状态（在线／思考中）、"N 个任务进行中"。
- "整理上下文"按钮代替原型的"新对话"（Q11 派生 6）：手动触发一次压缩。

## 3. 右栏（只读，Q18）

### 3.1 工位

- 名片：名字、性格、记忆路径、主 agent 模型 / 任务 agent 模型、工作方式（原型 `Workstation` 风格，内容来自设置）。
- 统计条：今日任务、进行中、需处理、已完成，外加**今日用量**（token／估算费用，Q12 派生 2）。
- 筛选：全部、进行中、排队中、需处理、已完成；排序：最新／最早。
- 任务行：标题、粗略状态（01 §3）、编号、所属项目、耗时或完成时刻。**没有进度条、没有技能标签**（Q13/Q16）。

### 3.2 任务页

| 区块 | 内容 |
| --- | --- |
| 头部 | 标题、状态、编号、cwd、mode、模型、耗时、用量 |
| 简报 | 原话（逐字）＋备注＋上游任务 |
| 时间线 | 按运行分段（第 1 次、第 2 次…）；worker 的叙述、工具卡、汇报、问题与回答、门与决定、作业与服务事件 |
| 访问痕迹 | 读过的文件、写过的文件、删过的文件、访问的域名、作业、服务（02 §5）；shell 访问标注"未知" |
| 底部 | 只读说明＋"在主对话中提及"（把 `@T-1045` 填入输入框）＋"在此目录打开终端" |

没有输入框，也没有停止、重试、续接按钮（Q18）。

### 3.3 浏览器（Q20）

- Electron `WebContentsView` 内嵌：地址栏、后退、前进、刷新；多标签沿用右栏标签体系。
- 起始页 `rally://start`：列出本地服务（所属任务、名称、端口、状态），点击即打开预览；每个服务有"停止"按钮（04 §5.2 的待定细节）。
- 隔离：独立 session partition，`nodeIntegration: false`，`contextIsolation: true`，`sandbox: true`，页面拿不到任何 Rally IPC。
- agent 不操作这个浏览器；浏览器自动化由用户配置 MCP（Q19）。

### 3.4 终端（Q20）

- xterm.js＋node-pty（ConPTY）。默认 shell 为 PowerShell 7，没有则用 Windows PowerShell 5.1；初始 cwd 为当前项目，或从任务页打开时为任务 cwd。
- 可开多个终端标签；关闭标签即结束对应进程树。
- 终端**归用户**：agent 不读不写（Q20 派生 1）。

## 4. 系统通知（附 A6）

窗口不在前台时，用 Electron `Notification` 发 Windows 通知：

| 事件 | 默认 |
| --- | --- |
| 问题被上升给用户、内门被上升给用户 | 开 |
| 任务失败、受阻 | 开 |
| 任务完成 | 开（设置可关） |

点击通知 → 窗口前置，并滚动到对应卡片。

## 5. 设置页（相对原型的变化）

| 分区 | 内容 |
| --- | --- |
| 身份 | 名字、性格、工作方式（附 A4） |
| 记忆 | 记忆文件路径、"用编辑器打开"、当前大小与 2k tokens 预算提示（Q23） |
| 供应商 | 编辑 `~/.rally/agent/models.json` 与 `auth.json`（明文，C3） |
| 模型 | 主 agent 模型＋思考强度；任务 agent 模型＋思考强度（Q22） |
| 工作区（新） | 默认工作区路径、最近项目、并发上限（附成本说明，C6）、作业转后台秒数（Q14）、默认是否需要批准（Q17） |
| 联网（新） | 搜索服务商与 API Key（Q19 派生 1） |
| MCP | 服务器列表；**逐个工具设风险档**（可逆／有对外代价／不可逆，Q19 派生 3） |
| Skills | 沿用 Pi skills 列表 |
| 项目信任（新） | 已信任的项目，可撤销（附 A3） |
| 外观、关于 | 沿用原型 |

首次引导（原型 `Onboarding`）步骤：供应商与 Key → 两个模型 → 默认工作区 → 记忆位置（可跳过）。

## 6. 开源复用选型（Q20）

许可证于 2026-11-08 通过 GitHub API 核实。

| 组件 | 用途 | 许可证 | 状态 | 结论 |
| --- | --- | --- | --- | --- |
| xterm.js（`@xterm/xterm`＋fit/web-links/search/unicode11 插件） | 终端渲染 | MIT | 活跃 | **直接依赖** |
| node-pty 1.1.0 | Windows ConPTY 伪终端 | MIT（GitHub 显示 NOASSERTION，是因为 LICENSE 里有多份 MIT 声明） | 活跃 | **直接依赖**；要求 Windows 10 1809+；安装时先取预编译包，失败再走 node-gyp |
| Tabby | 参考其 xterm＋node-pty 集成（会话、编码、resize、进程清理） | MIT | 活跃 | 参考或摘取代码，保留版权声明 |
| electron-browser-shell | 参考其 `WebContentsView` 标签管理与地址栏 | MIT | 活跃 | 参考或摘取代码 |
| Min | 浏览器交互细节参考 | Apache-2.0 | 活跃 | 仅参考 |
| Hyper | — | MIT | **已归档** | 不选 |
| Wave Terminal | — | Apache-2.0 | 活跃 | 架构不同（Go 后端），不选 |

## 7. 原型组件映射

| 原型 | 去向 |
| --- | --- |
| `ChatPanel` | 主对话；新增系统行、派发卡、问题卡、确认卡、分隔条；"新对话"改为"整理上下文" |
| `ToolSteps` | 改为渲染 `ToolResultEnvelope`（02 §5），主对话与任务页共用一套组件 |
| `status.tsx` | 改为 01 §3 的推导表（多出待批准、需处理的三种细分、无需处理、已取消） |
| `RightPanel` | 保留标签体系：工位、任务、浏览器、终端 |
| `Workstation` | 保留名片与统计；去掉进度条与标签；新增今日用量 |
| `TaskView` | 只读；去掉进度条；新增简报、按运行分段、访问痕迹、"在此目录打开终端" |
| `BrowserView` | 换成 `WebContentsView`；起始页列出服务 |
| `TerminalView` | 换成 xterm.js＋node-pty |
| `Settings` | 按 §5 调整分区 |
| `Onboarding` | 按 §5 末尾调整步骤 |
| `CommandPalette` `TitleBar` | 沿用 |

不从原型继承：任务进度条与百分比、技能/来源标签、任务页按钮与输入框、"新对话"、按任务的审批开关、模拟终端命令集、浏览器书签。
