# 附件与媒体资源系统设计

2026-11-21。实施设计与落地记录；产品边界以 `superagent/00-问答记录.md` 为准。本文件落实 HANDOFF 第二项，包含本轮用户追加的“从目录查看图片”，并保留未来图片、音频、视频生成与交换的入口。以下数值是可调整的实现默认值，不是新增用户决定。端到端代码及离线验证已落地，真实设备/视觉待用户验收。

## 现有能力和断点

- Pi 的 `createReadToolDefinition` 已保留在 `packages/coding-agent/src/core/tools/read.ts`，与 `example/pi` 对应实现一致，支持 JPG/PNG/GIF/WebP/BMP 检测、图片处理与模型图像内容块。
- 主 Agent 经 `router-tools.ts` 的动态 cwd 包装调用；Worker 经 `file-versions.ts` 包装读取，保留图片检测和读后被改检查。`tests/attachments/directory-read.test.mjs` 已用实际 PNG 验证两条包装链返回 image block，Worker 留下文件指纹。不代表真实模型识图已验收。
- 实施前 `MainAgent.send` 与 `chat:send` 只收文字，`Quote.attachments` 是旧 path/mime 类型；本轮已升级稳定资源引用并贯通输入、任务、工具结果和 UI。工具能看图片不等于客户端能展示/交换附件，需以实际链路测试为准。
- 云端请求是有 1 MiB 限制的 JSON；事件窗口 8 MiB、读取缓存约 8 MiB。禁止将原图或文件 base64 塞入这些链路。QQ 邮箱已能保存附件，可复用保存后的本地文件导入能力。

## 必须贯通的场景

| 来源 | 运行位置 | 行为与结果 |
| --- | --- | --- |
| 粘贴、拖入、文件选择 | Windows 本地 | 同一待发送队列；导入运行时资源库；消息可仅含附件；图片实际送模型 |
| 文件选择、粘贴、拖入（平台支持时） | Windows/Android 云端 | 上传到 VPS，进度/取消/重试；成功后发送稳定引用，其他设备按需读取 |
| 目录里的已有文件 | 本地目录或 VPS 目录 | Agent 的 ls/find/read 保持工作；支持把读到的图片或指定文件登记成资源、展示给用户；不尝试从 Android 读取 VPS 绝对路径 |
| Worker 生成的文件、邮箱下载文件 | 执行任务的运行时 | 导入资源、关联任务与汇报；主对话和任务页能打开并下载；源文件后续变更不偷偷改变已发送内容 |
| 图片/音频/视频生成工具 | 执行任务的运行时 | 使用同一资源登记协议；生成状态/进度/失败与最终资源分离；不以文件卡片宣称模型能理解所有媒体 |

## 资源、引用与存储

使用运行时统一 ResourceStore（本地/云端相同实现），保存在 `~/.rally/resources/`，随状态备份。二进制在 `blobs/` 中以内容 SHA-256 命名，元数据和引用关系由 SQLite 持久化。客户端的绝对路径、临时 URL、Blob URL 均不得成为消息附件的身份。

- Resource：稳定 UUID、原始展示名、检测媒体类型、大小、hash、创建时间、来源（upload/directory/tool/generated）、可用状态。持久记录来源路径仅在运行时使用，不把任意路径变成客户端读取权限。
- ResourceRef：`id/name/mime/size`；由消息、任务输入和工具调用持有，所属关系记录为 owner 引用。原话复制资源 ID；续接、压缩、重启后仍可找到同一资源。实例身份由当前连接约束，跨实例 ID 不可用。
- Upload：设备所有者、uploadId、预期长度、已持久化 offset、临时文件、更新时间、状态。完成校验并原子提交才创建 ready 资源；取消不能留下可发送的半文件。
- 产物通过任务、运行和工具调用关联多个 ResourceRef，生成状态沿用现有工具/任务状态，尚无独立 Artifact 表或生成服务。原件与 thumbnail 派生件分开；poster/transcoded 保留协议扩展方向，未实现自动转码。
- 元数据中的尺寸、时长和派生件是可选项；不能解码时仍保留原件下载。文件格式检测不能只相信扩展名或客户端声明。

目录导入应生成内容快照，确保消息里的图片不会随项目文件变化。大文件使用流式复制/哈希；前后 stat 与文件身份复核，发现改动时要求重试。只接受普通文件，目录、设备、管道与逃逸链接拒绝。Worker 导入范围来自任务 cwd/产出/已获原话引用资源；主 Agent 只读查询可展示已读取文件，资源登记属于系统展示副作用，不能扩大项目写权限。资源工具不能执行文件。

## 传输边界与异常处理

小型元数据走共用 API/IPC；二进制走独立鉴权接口。所有桌面 IPC 名称集中声明于 `src/shared/ipc.ts`，原生层继续持有设备凭据。

1. begin(name,size,mime) 创建设备所属临时上传，返回 uploadId/offset/chunkSize。
2. 传输原始字节到独立上传接口（建议每块 1 MiB，按 offset 条件追加）。同一块重复提交需校验已存在字节；offset 不符返回正确位置。流式转发控制台服务到运行时，避免整文件驻留内存。
3. status 查询已落盘 offset，重连后续传；complete 校验长度/hash并完成原子登记；cancel 删除该设备的临时上传。客户端换服、取消、卸载时中断旧连接，拒收旧响应。
4. 默认每消息最多 10 件、每文件 1 GiB、图片模型输入另按 Pi/模型限制处理；限制由服务端执行。并发上传最多 2 件，临时文件设置设备配额和 24 小时过期清理，超限给可理解错误。
5. 文件读取支持 GET/HEAD、单一 Range、Content-Length/Content-Range、ETag，错误范围返回 416。接口支持媒体 seek/分段读取，原生下载当前从头下载，尚无跨重启下载续传。慢传输使用独立超时，不沿用 30 秒 JSON 请求时限。

客户端传输适配器：Windows 本地用受限 IPC 与文件流；云端由原生层转发鉴权 HTTP；Android 以原生文件 URI/流处理选择和保存，不能要求用户提供 Android 绝对路径。若 Gecko 的 File/Blob 通过扩展桥传递，采用有上限的分块与背压，不一次 base64 编码整段视频。

预览 URL 为临时能力，永不持久化到消息。优先采用原生鉴权资源读取；如媒体元素需要直接 URL，运行时签发绑定设备、资源、只读方法、短 TTL 的访问票据，返回后端生成的指定 URL。票据不得授予目录或其他资源访问；吊销即时终止活跃传输，过期时客户端重新申请。预览页面不加载外部内容，不将设备令牌拼到 URL。部署必须使 Range 和 CORS 与选定传输方案一致，相关实现需要集成验证后定稿。

## Agent 输入、读取与输出

- 发送接口升级为文字 + 资源引用，保留旧纯文本调用兼容。服务器验证 ready/所属实例/可访问；空文字但有附件允许。幂等键由文字与有序资源 ID 共同决定。
- 有图像能力的模型获得 Pi `ImageContent`（使用现有处理/缩放）；普通文件以描述与运行时受控路径交给工具。非视觉模型明确提示图片未进入视觉输入，仍保留资源引用供 Worker 或其他模型读取。
- Router 到 Worker 的派发、追加、代答都逐字保留原话与附件 ID；宿主解析引用并注入适当内容，不让 Router 用文字路径冒充附件传递。
- 继续复用 read 看目录图片；捕获图片工具结果与原始文件来源，将其转为展示资源引用。对没有文件路径的 MCP image block，导入图像字节并关联 toolCallId。不要把模型端 image block 从实际工具结果中删去。
- 提供显式产物发布工具，接收执行环境中的文件路径并返回资源引用；Worker 生成图片、报告、音频、视频后可发布。汇报携带资源引用，主 Agent 可以转述并展示，不能凭模型文本伪造资源。
- 本轮提供媒体文件上传、交换、预览与下载基础。模型直接音频/视频理解必须按实际供应商协议能力接入；当前 Pi 通用图像路径不等同于音视频输入。生成供应商通过已有工具/MCP/脚本接入，不虚构内置生成功能。

## 交互和生命周期

待发送队列统一处理粘贴/拖拽/选择：图片缩略图、普通文件图标、大小、上传进度、取消/移除/重试。全部 ready 才允许发送，失败保持文字和队列；切会话/换服先清理临时引用。重试消息保持同一请求 ID，不重复创建消息或任务。

消息与任务页显示资源卡片；图片点开在右侧新建预览标签，已有同资源标签可激活；移动端复用全屏右栏和返回栈。支持图片、纯文本/代码（体积受限并转义）、浏览器支持的音视频播放；PDF 是否内嵌需跨端验证，不支持时仍提供下载。HTML/SVG/可执行内容不在应用来源下直接运行；Office/压缩包默认元数据与下载。媒体解码失败显示格式原因，原件仍可保存。

下载按钮使用 Windows 保存对话框、Android 系统保存位置，展示进度/完成/失败；取消清理临时下载，不覆盖未确认的目标。缓存仅保存必要元数据和有界缩略图；原件按需加载，视频不进入 IndexedDB 全量缓存。

资源引用计数/可达性覆盖主会话历史、任务原话、产物和派生件。归档不会删文件；彻底删除任务只释放它独有引用，共享消息/任务仍使用则保留。新建主会话不删除旧历史与任务资源。未发送上传过期清理；有引用原件默认保留，自动清理不能误删用户项目源文件。缺失资源仍显示卡片与原因。备份包含资源元数据、原件、事件与会话，以只读快照或停机一致性方式执行。

## 验证与交付顺序

1. 资源契约/存储：流式导入、目录看图、内容稳定性、去重、重启恢复、引用/删除隔离。
2. 本地完整链：粘贴/拖拽 → 发送 → 主 Agent/Worker 图像输入 → 生成/登记 → 消息/任务卡 → 新标签预览 → 保存。
3. 云端完整链：设备鉴权、二进制传输/续传/Range、Windows/Android 选择与保存、跨端元数据同步，缓存不含文件字节。
4. 离线异常：取消、超限、错误 offset/hash、断网、吊销、换服、路径穿越、文件在导入中变更、资源缺失、非视觉模型与不支持播放格式。
5. 使用 faux provider 检查实际模型请求含图像块，Worker 原话附件可用；不调用真实供应商。构建与定向测试由开发侧执行，平台视觉和真实设备体验由用户验收。

完成标准是上述端到端链路与异常均有对应证据；仅完成上传按钮、缩略图或资源表不能勾选 HANDOFF 第二项。

- `src/shared/resources.ts` 定义持久资源元数据、引用、上传状态与大小限制；`src/main/resource-store.ts` 使用运行时独占的 SQLite 元数据与按 SHA-256 存放的文件，随 Supervisor 创建并在请求/Agent 清理后关闭。
- 已实现 begin/status/append/complete/cancel、按设备隔离未发布资源、1 MiB 分块和 1 GiB 单文件限制、重复分块内容校验、重启按已提交 offset 恢复、流式哈希、原子发布、相同内容存储复用及损坏副本修复。
- 目录导入检查允许根目录和普通文件，保存独立内容快照；共享引用按 owner 保留/释放。启动按所有主会话历史和现存任务恢复引用后清理，之后每小时维护；事件损坏时关闭自动回收。只清理资源库中匹配托管名称的过期文件，不删项目源文件。
