## 产物契约

同一个 `vX.Y.Z` tag 必须与根 `package.json` 的版本一致。一次正式发布恰好包含：

```text
Rally-X.Y.Z-setup.exe
Rally-X.Y.Z-android-arm64-v8a.apk
Rally-X.Y.Z-android-armeabi-v7a.apk
Rally-X.Y.Z-android-x86_64.apk
rally-server-X.Y.Z-linux-x64.tar.gz
SHA256SUMS
```

Android 每个 APK 都是可独立安装的完整应用，只包含对应 ABI 的原生内核，不需要一起安装，也不生成 universal APK。安装与升级保持包名 `dev.rally.mobile`、版本号和相同正式签名。版本码按 `major * 1000000 + minor * 1000 + patch` 计算，minor/patch 应小于 1000。

## 本机构建

依赖安装始终使用 `npm install --ignore-scripts`（CI 使用 `npm ci --ignore-scripts`）。Electron 二进制通过 `node node_modules/electron/install.js` 明确安装；不运行依赖的任意生命周期脚本。

Windows：`npm run dist`，然后 `node scripts/verify-windows.mjs`。主程序、安装器、卸载器、任务栏和托盘共用 `icon.png` 生成的 ICO；校验检查版本、运行资源、图标尺寸和打包配置。当前不使用 Windows 代码签名，不把生成文件标为已签名。

Linux：在 Linux x64 上运行 `npm run build:server` 和 `bash scripts/cloud/package-linux.sh`。脚本在独立临时目录安装生产依赖，包含构建所用 Node/npm，跑离线协议、Agent 和附件测试后打包，不裁剪开发工作区的 node_modules。安装步骤见 `deploy/linux/README.md`。

Android 环境：JDK 17、Android SDK Platform 37.2、Build Tools 36.0.0；项目固定 Gradle 9.8.0、AGP 9.5.2 和 GeckoView `160.0.20261116130455`，使用仓库 wrapper 和依赖锁。

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-17'
$env:ANDROID_HOME = Join-Path $env:LOCALAPPDATA 'Android\Sdk'
$env:GRADLE_USER_HOME = Join-Path $PWD '.artifacts\gradle-home'
npm run build
node scripts/cloud/build-android.mjs --debug
```

已缓存依赖时可加 `--offline`。调试密钥首次生成在忽略的 `.artifacts/android-debug.p12`，保留它才能覆盖旧调试包。APK 位于 `release/`，名称带 ABI 与 `-debug`。验证器逐个检查 ZIP 路径、renderer 资源、Gecko 原生库、许可证、预览策略，并使用 SDK 的 apksigner 检查签名，要求三个 ABI 使用同一证书。

## Android 正式签名

本仓库正式签名已由发布者授权生成，保存在本机 `.signing/android-release/`，备份包为 `.signing/rally-android-release-backup.zip`；整个 `.signing/` 纳入 `.gitignore`，目录仅允许当前用户、SYSTEM 和本机管理员访问。私钥、密码和备份不入库、不附在 Release。公有证书 SHA-256 为 `393a85b5107a78dbc4fa85e62365209532be0aa07783f65c479eac11b107d264`，GitHub 已配置四项签名 Secrets 及指纹变量。请继续保护并离线备份整个签名目录，后续版本沿用该签名。

由发布者创建并离线备份长期密钥；不要把密钥或密码写入代码、聊天、日志和仓库。若已有已分发正式版本，必须沿用旧密钥，不能另建替换。可在本机交互式执行以下命令，让 keytool 提示输入密码：

```text
keytool -genkeypair -keystore rally-release.p12 -storetype PKCS12 -alias rally-release -keyalg RSA -keysize 3072 -validity 10000
```

本机正式构建需通过安全环境配置 `ANDROID_KEYSTORE`（绝对路径）、`ANDROID_KEY_ALIAS`、`ANDROID_STORE_PASSWORD`、`ANDROID_KEY_PASSWORD`，然后运行 `npm run dist:android`。脚本拒绝缺少凭据、调试证书或 ABI 证书不一致的包。

在 GitHub 仓库 **Settings → Secrets and variables → Actions** 配置：

| 名称 | 内容 |
| --- | --- |
| Secret `ANDROID_KEYSTORE_BASE64` | 正式 keystore 文件的 base64 |
| Secret `ANDROID_KEY_ALIAS` | 正式 alias |
| Secret `ANDROID_STORE_PASSWORD` | keystore 密码 |
| Secret `ANDROID_KEY_PASSWORD` | 私钥密码 |
| 可选 Variable `ANDROID_CERT_SHA256` | 公有签名证书 SHA-256 指纹，可带冒号，用于防止误用证书 |

工作流仅在 runner 临时目录展开密钥，结束时清理；不会将它放进 artifact。证书指纹可公开，私钥与密码不可公开。

## Tag 与草稿 Release

完成代码审查、定向检查和本地验收，再由发布者确认版本并提交、推送。未经用户要求不自动提交或推 tag。

```text
git tag -a vX.Y.Z -m "Rally X.Y.Z"
git push origin vX.Y.Z
```

工作流在 Windows/Linux/Android runner 构建；所有 job 成功后合并五个文件，`scripts/release-checksums.mjs` 拒绝缺包、额外调试包或版本不符并生成摘要，校验后创建**草稿** Release。不会自动对外发布。

从草稿下载全部产物与 SHA256SUMS：验证 Windows 安装/升级、Android 目标 ABI 安装与签名升级、Linux 干净安装和保留数据升级，核对附件收发与模式切换，再手动发布草稿。没有运行的 CI 或真实设备步骤必须明确标为待验收。

如果只有构建工作流需要修复，可将修复提交到默认分支，再运行 `gh workflow run release.yml --ref master -f release_tag=vX.Y.Z`。工作流始终检出指定的原始 tag，检查其版本，不移动 tag 或混入默认分支的应用代码。应用代码有变化时创建新的版本 tag，不强推已经分发的 tag。临时失败也可直接重试原运行；重试前检查已有草稿及 artifacts，避免混入不同代码的产物。保存正式签名、校验摘要和上一版服务器目录，以支持可核对的升级与恢复。
