# 世界感知与任务上下文

这两项能力由主 Agent 按任务需要使用，不增加新的动态上下文快照，也不改变教练触发方式。

## 时间、地点与天气

- `world_time`：按 IANA 时区查询当前日期、时间、星期和 UTC。没指定时区时返回执行主机时间，并明确标明来源；云端主机的时区不能当成用户的时区。
- `world_location`：将明确给出的城市或地区查成最多 5 个候选，附国家、行政区、坐标与时区。同名城市先澄清，不自动采用第一项；不读 GPS、IP 定位或设备位置。
- `world_weather`：按已确定的坐标查询当前模型天气与从当地今天起的预报，默认 3 天、最多 7 天。返回数据时间、来源和单位；缺数据保持空值，网络失败不编造天气。

主 Agent 与内置 Worker 都能调用；外部 Claude/Codex Worker 仍使用各自的工具。工具描述引导 Agent 先用用户已经提供的信息；当城市、地区或时区会明显帮助当前任务时，自然询问缺失项。允许用户不回答，不收集无关信息，不把查询变成后台轮询。

地点与天气使用 Open-Meteo，地点来源含 GeoNames，展示结果时署名。免费公共接口面向非商业用途；商业部署可在执行主机配置 `RALLY_OPEN_METEO_API_KEY` 并重启，切换到官方客户接口。密钥不交给模型。每次网络请求上限 15 秒，沿用网络取消、闲置保护和 Worker 的访问记录。具体上游字段和来源见 [工具契约](Prompt/tools-Description/world.md)。

## 派发背景只填两个数字

2026-11-26 根据用户实测简化，替代逐条消息 ID / 原文摘录方案：

| 参数 | 含义 | 新任务默认 |
| --- | --- | --- |
| `context` | 自动携带最近 0–30 轮主对话 | `0` |
| `memory` | `0` 不带；`1` 带 USER、PREFERENCES、RECENT 三份当前记忆全文 | `0` |

例如 `context: 3, memory: 1`，由 Rally 自动准备最近 3 轮对话与全量笔记。模型不需要先调用 `chat_search`、挑消息 ID 或摘原文。需求与权限仍由 `quotes` 承载；`note` 保留 30 词上限，仅用于简短消歧。

一轮是用户的一条消息，以及它之后、下一条用户消息之前的可见助手回复；多次助手回复仍算同一轮。排除本次派发请求及其回复，不把工具调用、thinking、系统回告当作一轮，也不复制这些内容或附件正文。轮数以主对话记录为准，历史不足就携带实际轮数，压缩和重启不需要模型重新找 ID。新主会话只使用自己的记录。请求处理中排队的新消息不会改变本次背景的截止点。

聊天仍限制体积：单条最多 4,000 个 Unicode 字符，总计 60,000，超长内容自动截短并标 `truncated: true`；派发回执返回实际轮数、消息数、记忆文件与截短数量。记忆按现有每文件 3,000 / 4,500 / 4,500 UTF-8 字节预算完整复制，空文件省略；损坏或超预算时明确报错，不悄悄改为部分笔记。

## 保存与接续

宿主保留消息 ID、角色、时间、所属轮次或记忆文件名，并冻结实际文本。Worker 收到时明确标为背景，不是新增需求或授权。记忆之后被修改，已有任务的副本也不自动改变。

`task_update` 和 `task_resume` 使用同样的两个开关，各自独立：

- 省略某个开关：保留该部分的旧快照。
- `context: 0`：清掉选定聊天；`memory: 0`：清掉选定记忆。
- 填正轮数或 `memory: 1`：重新读取并替换对应部分。

续接保留原会话历史，因此清空选定背景不表示删除模型已见过的文字。内置与外部 Worker 使用同一份背景，事件日志、任务快照和闲置恢复保留这份数据。旧版已经保存的原文摘录仍可恢复，不再向模型提供逐条摘录参数。

主对话自动状态和任务板不塞入这些背景；`task_read` 的单任务 card 可按需查看。Worker 能读取自己任务的背景，上游任务的背景不向下游共享。

定时计划 `schedule_create` 也使用两个开关，在创建时冻结并复制给每次到期执行，不每轮重读记忆。修改时间保留原背景；当前没有在计划上单独修改背景的接口。天气、当前时间等由到期 Worker 临时查询。
