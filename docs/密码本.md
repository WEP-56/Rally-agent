# 密码本

密码本集中保存 Rally 任务需要的账号和密钥，可用于命令行、HTTP API、数据库、SDK、脚本以及浏览器。设置中的「密码本」沿用原「网站账号」入口和已有数据。

## 保存和管理

需要凭据时，助手先查询已保存的启用项；没有合适记录时，在对话中发起私密填写申请。弹窗提供两种类型：

- **账号和密码**：填写账号与密码。网站登录继续按准确的 HTTP(S) 来源匹配。
- **仅密钥 / Token**：只填密钥，无需编造用户名。服务可以是 Gitee、数据库名称等描述，也可以是网站来源。

可给记录起一个名称，用于区分同一服务的多个身份或用途。名称和服务会被助手看到，请勿把密钥填到这些公开字段中。保存值保留首尾空格，密码本不向客户端或模型返回秘密原文。

例如告诉助手“使用 Gitee Token 维护这个项目”，在申请弹窗选「仅密钥 / Token」并保存；后续任务能查询该条目并在命令行或 API 中使用。保存成功只代表凭据已可用，是否有权限仍需通过实际操作验证。

启用、停用、修改和删除都在密码本中进行。停用或删除立即阻止后续取用；已启动进程和既有登录态继续存在，需要另行停止进程或清除浏览器登录态。修改后，新调用使用新值。

## 工具接口

主助手与内置 Worker 使用 `credential_list` 查询公开元数据；`credential_request` 仍由主助手发起。Worker 在缺少凭据时回报服务、用途和需要的类型。

命令工具 `bash`、`powershell`、`git`、`github` 和 `service_start` 支持：

```json
{
  "credentialEnv": {
    "GITEE_TOKEN": { "id": "由 credential_list 返回的 ID", "field": "secret" }
  }
}
```

`field` 默认是 `secret`，表示密码或 Token；账号类型还支持 `username`。Bash 通过 `$GITEE_TOKEN`、PowerShell 通过 `$env:GITEE_TOKEN`、脚本通过进程环境读取。宿主在实际启动前重新检查记录是否存在且启用，只向本次调用及其子进程注入，不修改 Rally 自身环境或其他任务的环境。Git 仍需凭据 helper 消费环境变量；仅设置任意 Token 变量不会自动完成 Git 认证。`github` 可绑定 `GH_TOKEN`。

`http_request` 的请求头值和字符串正文支持 `{{credential:ID:secret}}` 与 `{{credential:ID:username}}`，例如 `Authorization: Bearer {{credential:ID:secret}}`。URL 不替换凭据，跨来源重定向仍移除请求头。正文是字面替换；需要 JSON 转义、表单编码、Basic Auth 或自定义协议时，使用读取环境变量的脚本完成编码。

浏览器继续用 `browser_login`，只接受当前来源的账号密码记录；Token 不会误选为网页登录账号。外部执行器沿用独立工具边界，需要密码本的工作由内置 Rally Worker 执行。取用凭据不会授予提交、推送、发信等动作的额外权限，既有任务范围和审批规则继续生效。

## 存储和输出

沿用 Agent 配置目录中的加密 `website-accounts.txt`；Windows 使用系统安全存储，Linux 使用部署 vault key。旧记录无需手工迁移，缺少类型时按账号密码读取。客户端 IPC 和云端业务接口仍只返回公开元数据。

已注入秘密的原文、URL 编码、JSON 转义和 Base64 回显，会在进入命令日志、后台通知和模型结果前被过滤；stdout/stderr 分别处理跨数据块的秘密。HTTP 响应及错误也经过过滤。这不构成任意脚本的安全沙箱：自定义编码或脚本主动将秘密写入文件不属于输出过滤。提示词要求避免输出密钥，只有用户明确要求时才将其写入配置。
