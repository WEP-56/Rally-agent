# 闲置保护

默认开启，固定为连续 72 小时没有用户发言。本地与云端都由执行主机判断，不依赖客户端保持连接，也不由模型决定是否暂停。当前不提供关闭开关。

## 计时与恢复

- 主对话中的有效文字或附件消息、已验证的飞书/QQ 用户消息，以及用户对任务问题的直接回答，都算用户发言。
- 打开或聚焦窗口、查看任务、批准任务或权限、自动回告、Worker 汇报、教练点子、邮箱来信都不会续期，也不能解除暂停。重复投递的已接收 IM 消息不续期。
- 最后发言时间与暂停状态写入事件记录。重启、升级、新建主会话不会重新计时。首次使用还没有发言时，从首次建立这份状态开始计时；已有用户从历史最后一次发言开始。
- 到期后关闭新活动入口并中止正在运行的活动。用户下一次发言会等待停止工作完成，再恢复执行；若停止失败，保持暂停并报告错误。
- 界面顶部显示暂停原因与“发送一条消息即可恢复”。桌面与移动云端共用同一主机状态。

## 暂停范围

停止主 Agent、Worker（包括外部执行器）、定时派发、教练点子与记忆整理、中继唤醒、自动重试和缓存预热。正在运行的托管后台作业、本地服务、Agent 浏览器及其它托管进程也会停止。手动整理上下文在暂停期间不可用，避免产生模型费用。

保留本地数据、任务记录、设置和接收用户消息的连接。客户端仍能查看数据、修改设置、取消任务，并从主对话或已连接的 IM 发言恢复。闲置保护不向模型上下文反复注入时间或状态；只有固定的规则说明和恢复某个任务时的一次性说明。

## 任务和定时计划

- 不改写计划的启停开关、任务批准状态，也不把未完成的任务标为失败。手动停用的计划恢复后仍停用。
- 正在执行的 Worker 保留原运行记录、会话历史与任务输入；恢复后接续同一个运行。等待回答的任务保留原问题，等回答后继续；原先受阻、待批准或因重启中断的任务仍遵守各自的恢复条件。
- 恢复说明会要求 Worker 先核对文件和外部结果，再决定是否重试中断动作。外部执行器重新建立自己的会话，并接收原任务要求与恢复说明。
- 后台作业和服务会被停止，而不是冻结进程。Worker 根据当前进展决定是否重开；已经完成的任务所留的服务不会因为用户发言就自动重启。
- 暂停期间不派发新定时任务。恢复后沿用 [定时任务](定时任务.md) 的合并规则：漏掉的重复只合并补一次，仍受允许运行时段、前一轮未结束和批准状态限制，不逐条补齐。到期的一次性计划保留，等待恢复后派发。

保护只能停止后续活动。请求中止前已产生的用量、已经执行的外部动作无法撤回；Rally 之外已经部署的服务和定时器也不会被这个本地保护停止。

## 实现入口

`src/main/supervisor/inactivity.ts` 管理计时与持久状态，`index.ts` 负责停止和恢复各模块。`session.ts` 在模型和工具入口拦截；定时器、调度器和 Worker 同时检查宿主状态。现有主对话状态通道携带 `inactivity`，不新增独立的客户端权限或唤醒开关。

离线回归使用 faux provider 与本地测试进程，覆盖到期边界、历史恢复、时钟回拨、停止与唤醒的并发、定时任务、教练、IM 去重、工具跨越到期点、运行中 Worker、后台作业与本地服务。界面视觉由用户验收。

## 用户消息队列

收件箱和 IM 回复回传也受闲置保护控制。读取、继续或重试队列不续期；收到新的真实消息才续期。未处理消息持久保留，主 Agent 处理中断的消息标为未完成，需明确重试以核对已经发生的操作；详见[用户消息收件箱](用户消息收件箱.md)。
