# Role Workers：Claude Code / Codex 接入调研\n\n日期：2026-11-24\n状态：代码接入已完成基础实现；权限、MCP 桥接与最终打包运行仍待验收。\n\n## 目标与既有约束\n\n- 角色仍是 Rally 的普通 worker，由主 agent 基于任务决定是否派遣；外部 agent 不产生 Rally 下级任务。\n- 首个接入 Claude Code，之后 Codex；两者走共用的执行生命周期。\n- Skill 仍是推荐提示，MCP 不做角色级筛选。\n- 外部执行器是实验性配置：角色编辑页中的“实验性功能”分组默认收起。\n- 原生 Rally worker 仍从 Rally 模型列表选择模型；Claude Code / Codex worker 分别从 ACP 会话暴露的模型配置项中选择，不再要求模型出现在 Rally 模型列表。\n- 外部 CLI 沿用其本机配置与登录状态；Rally 不复制或保存其凭据。\n- 设计、实施和调研资料只放 `roles-docs/`。\n\n## 调研结论\n\n### 接入方式\n\n采用 ACP（Agent Client Protocol）stdio 子进程作为共用边界：Rally 为一次 worker 运行启动 ACP adapter，创建会话、提交任务消息、接收增量文本/工具事件/用量/结束状态，并在任务取消或关闭时取消会话、关闭进程。不要让 Rally 直接解析 Claude Code 或 Codex 的私有事件协议。\n\nClaude 官方 ACP adapter 使用 Claude Agent SDK；仓库 README 声明支持文本/图片、工具权限请求、嵌套 subagent transcript、交互终端和通过 ACP 提供 MCP 等能力。adapter 有独立可执行文件发布，也支持复用本地 Claude CLI。\n\nCodex 官方 ACP adapter 通过 ACP stdio 服务启动 Codex App Server；提供 ChatGPT 登录/API key/兼容网关认证，并将模型、审批模式、sandbox 模式和 Codex 权限配置暴露为会话选项。两种 adapter 均可复用，但 Rally 需要自行负责其安装/定位、认证状态反馈、会话映射和终止。\n\n### 子 agent 约束\n\n只在 ACP 初始化时不声明 subagent 客户端能力，不足以证明外部执行器没有创建子 agent：\n\n- Claude adapter 支持 Claude Agent SDK 的 Agent/Task 子 agent；未启用子会话呈现时，部分调用只会回落为普通工具事件，内部执行并不会因此自动禁用。\n- Codex ACP 的 v1 在未声明 subagent 能力时会把子 agent 生命周期回落为普通工具调用；这也是事件呈现方式，不等于关闭 Codex 的内部 delegation。ACP v2 则默认包含 subagent 会话。\n\n所以实现时必须通过 Claude 禁用 Agent/Task 工具、Codex 原生配置关闭 delegation，或通过可验证且失败即拒绝的等效机制落实此约束。若 adapter 没有可靠开关，应将该 executor 保持不可用，不能仅靠系统提示词或隐藏事件。\n\n### Rally 运行规则的映射\n\nACP 是会话与事件协议，不会自动继承 Rally 的 worker 生命周期、目录范围、只读/可写模式、任务授权、审批、审计、取消与特定 Rally 工具。外部 Agent 有自己的文件、终端和联网执行环境。Rally 必须显式传递 cwd/工作区与角色提示，并接管 ACP 的权限请求、文件变化与终止事件，才能声称行为与普通 worker 对齐。\n\nMCP 可经 ACP 提供给 adapter，但仍需为现有 Rally worker MCP 建立协议桥接；“角色不单独配置 MCP”不等于 adapter 自动能看到 Rally MCP。浏览器/站点账号等 Rally 专用工具也要逐项确认是否能以既有工具或 MCP 服务提供，不能假设 ACP 会自动接通。\n\n## 建议的实现分层\n\n1. **配置层**：角色增加可选执行器 `rally | claude-code | codex`，旧角色默认 `rally`；继续复用名称/头像/提示词/推荐 Skills/任务派发。\n2. **ACP Host**：一个共用 stdio JSON-RPC 客户端和 worker 生命周期适配层；负责启动/探测 adapter、初始化、会话/消息、事件转译、取消、超时与进程退出。适配器只处理 provider 特有配置和能力差异。\n3. **Rally Worker Bridge**：把任务事实、角色提示、cwd 和输出目录传入 ACP；把文本、用量、工具调用/权限请求、文件变更及任务结束映射回 task store、worker 事件、approval/gate、audit。\n4. **Provider adapter**：Claude adapter 先接；Codex adapter 复用 ACP Host。adapter 包/二进制不从会话中临时 npx 下载；实现前确定由应用携带固定版本还是用户安装并由 Rally 探测。\n5. **设置与派发**：设置页提供执行器选择与安装/认证状态；router 的角色目录保持执行器事实可见，派工仍使用现有 `task_dispatch` 和 roleId。\n\n## 实施边界\n\n1. ACP 模型目录来自对应 adapter 的 `session/new.configOptions`，筛选 `category=model`，显示其选项 label，并将选中 value 持久化到角色。不可用时不回退到 Rally 模型或静默使用默认模型。\n2. 角色外部执行器只在对应 ACP adapter 可启动且返回可用模型时可保存/派发；用户凭据保持在 Claude Code / Codex 自己的配置中。\n3. 外部 worker 使用 ACP 请求的 cwd、模式和会话生命周期；Rally 保持角色不能创建 Rally 子任务。只有已明确映射到 Rally gate 的操作才标为 Rally 审批，adapter 自己执行且 Rally 未接管的操作不能声称等同于原生 worker 工具审批。\n4. 配置和运行均发生在当前 worker 所在主机；桌面与云端分别检查该主机上的 adapter / CLI 安装和登录状态。\n5. 子 agent 禁用必须落实为执行器配置或可拒绝的 ACP 工具权限；不能只靠隐藏 ACP 子会话或在提示词中禁止。\n\n## 一手参考\n\n- Claude Agent ACP：<https://github.com/agentclientprotocol/claude-agent-acp>\n- Claude 子 agent 生命周期：<https://github.com/agentclientprotocol/claude-agent-acp/blob/main/docs/subagent-sessions.md>\n- Codex ACP：<https://github.com/agentclientprotocol/codex-acp>\n- Codex 子 agent 生命周期：<https://github.com/agentclientprotocol/codex-acp/blob/main/docs/subagent-sessions.md>\n- ACP v1 协议总览：<https://agentclientprotocol.com/protocol/v1/overview>\n\n本记录基于上述仓库 `main` 分支在 2026-11-24 的公开说明；实现依赖及行为需在 pin 具体版本后再以版本化源码/测试核实。\n\n\n\n## 2026-11-25 实施核验补记\n\n- 固定依赖 `@agentclientprotocol/sdk` 2.10.0、`claude-agent-acp` 0.110.1、`codex-acp` 2.10.0；主进程用同一 ACP v1 Host。CLI 随 npm 依赖提供，不运行时下载。Windows Electron 包把 Claude/Codex 两个原生可执行文件 `asarUnpack`，ACP 子进程通过 `ELECTRON_RUN_AS_NODE` 启动；Windows 启动器路径解析显式指向解包目录。\n- Claude 会话空掉用户/项目设置来源、钩子、MCP、Bash、Skill、Agent/Task 工具；工具集白名单按角色任务模式生成。Codex 保留用户 `CODEX_HOME` 登录及 provider 配置，但在子进程中关闭 delegation、hooks 及插件 hook 相关 feature，并显式选 `read-only` / `workspace-write` sandbox 模式。\n- Rally 外部 worker 会记录 ACP 文本、工具事件、按协议 usage 记录 token（Codex 按 turn 计，Claude 累计 usage 转换为增量；Claude 支持的美元 cost 按累计值转增量） 和 executor/model，并在终止时关闭 ACP session 与子进程树。外部执行器不注入 Rally MCP/browser/内部工具；ACP 权限提升请求统一拒绝。外部输出必须带最终状态标记，未标记不会误报完成。\n- ACP probe completed in development: Claude exposes 5 models and Codex 11 under an isolated temporary HOME and dummy loopback-only API key; selecting a model and read-only/write mode worked in both adapters.
